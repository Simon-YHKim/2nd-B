# 한국어 화면 끝말 검사

근거: `DECISIONS.md` 2026-10-14 22:33의 Q-261014-84 가·85 나와 `STYLE.md` B안.
사실·안내는 `~습니다`, 질문·제안과 사용자가 직접 하는 말은 해요체를 쓴다.
외부 글쓰기 스킬 전체를 도입하거나 모델 답 뒤에 교정 호출을 붙이지 않는다.

`npm run check:copy-endings`는 `locales/ko/**/*.json`의 모든 문자열을 읽는다.
새 문자열뿐 아니라 기존 문자열과 배열 항목도 검사하며 Git 기준 커밋이나 네트워크가
필요하지 않다. `npm run verify`와 동일 명령을 부르는 CI에 포함된다. 후보를 발견하면
파일·키·끝말을 출력하고 종료 코드 1을 반환한다. 빈 입력과 깨진 JSON도 실패한다.

이는 Q-261014-89의 `check:explanatory-copy`와 별도다. 설명형 문구 검사는
그대로 경고만 낸다. Q-84·85에는 끝말 검사에 대한 경고 전용 결정이 없으며,
현재 허용된 문구를 보존한 상태에서 새 이탈을 차단하는 검사를 구현했다.

## 보존하는 범위

| 범위 | 처리와 근거 |
|---|---|
| `profile.json`의 `contextImport.*` | Q-85에서 화면 전체 해요체를 승인했다. |
| `secondb.json`의 리마인더 안내 | `planSuggestion.oneOff.*`와 `reminderSavedNoReminder`·`reminderSavedReminderDenied`·`reminderSavedReminderFailed`. 루틴 안내나 대화 화면 전체는 제외하지 않는다. |
| 기존 동의 화면 17개 | Q-84 조사에 다음 동의 판본 때 다룬다고 적힌 `consent.json`의 17개를 현재 키·문구와 함께 고정했다. 새 키나 바뀐 평서문까지 면제하지 않는다. |
| 사용자 답·선택·입력 예시 | 실제 사용처를 확인한 키와 현재 문구만 보존한다. 키를 앱의 상태 안내로 바꿔 쓰면 다시 검사한다. |
| 한도 안내의 제안 | `drill.dayLimit`의 “지금까지 나눈 이야기를 저장하고 나중에 이어서 해요.”만 제안으로 보존한다. 같은 값 안의 앞선 사실 문장은 검사한다. |
| 질문·요청·인용 | 물음표로 끝나는 질문, `~나요`·`~까요`·`~세요`·`~셔요`, 짝이 맞는 따옴표 안 원문을 평서 안내로 바꾸지 않는다. |

두 승인 화면의 문구, 동의·안전 문구, 로케일 파일 자체는 이 검사 도입으로 바꾸지 않는다.
예외 파일·키를 넓히거나 새 사용자 발화 예외를 넣을 때는 실제 표시 역할과 결정 근거를 검토한다.
오류를 없애려고 승인된 고지의 뜻을 바꾸거나, 파일 전체를 예외로 만들지 않는다.

## 이 검사가 증명하는 것과 남는 검토

문장 끝의 `~아요/어요/해요/예요/돼요` 등 명시한 어미 후보를 찾는 결정적 검사다.
중간 문장·줄바꿈도 검사하며 `소요`·`필요` 같은 명사와 질문을 `요` 한 글자로 오탐하지 않는다.
완전한 한국어 형태소·의미 판정기는 아니다. 새로운 문맥의 제안이 후보로 잡히면
실제 화면의 발화 역할을 확인해 좁은 예외 또는 B안 문구로 처리한다. 자동 치환은 없다.

로케일 밖의 코드 리터럴, 모델 지시문, 생성된 모델 답, 사용자가 입력한 원문은 이 검사의
범위가 아니다. 따라서 통과를 앱의 모든 한국어 문장이 자연스럽다는 증거로 쓰지 않는다.
화면의 제목·안내·버튼을 함께 읽는 검토와 인터뷰 지시문의 실제 모델 측정은 따로 필요하다.

`scripts/__tests__/check-copy-endings.test.ts`는 두 예외의 경계, 동의 판본의 범위,
사용자 발화, 질문·인용 뒤의 별도 평서문, 제안 앞의 사실문, 여러 문장과 배열을 검사한다.
임시 폴더에 새 위반을 심어 실제 CLI가 종료 코드 1을 반환하는 것도 확인한다.
공유 저장소의 로케일을 테스트 중 임시로 바꾸지 않는다.
