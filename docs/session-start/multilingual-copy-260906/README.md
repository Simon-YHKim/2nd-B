적용했다. 새 언어팩을 출시한 것은 아니다. 앱 변경은 TTL-Work에 있고, 이 공유 브랜치에는
스토어 초안·문체 기준·변경 내역·패치를 보존한다.

- 소스에 따로 적힌 ID 문구 4개: 설정, 처리 기록, 저장 복구 안내, 제안 승인 안내.
- 세컨비 소개·선택 버튼·접근성 설명이 선택한 UI 언어를 읽도록 연결했다.

  한 구절의 예외가 뒤의 별도 주장까지 숨기지 않도록 검사한다.
- [STYLE.md](../../../STYLE.md)에 언어별 호칭·행동 설명·허용 문맥을 남겼다.
- [스토어 문안](../../store-copy/drafts.json)은 KO/EN/ES/PT/ID 5개 언어,
  메타데이터 35개와 촬영용 캡션 30개다. [미리보기](../../store-copy/review.html)에서 읽고 복사한다.

## 변경을 가져올 때

[changes.json](changes.json)은 로케일의 변경 전후 값,
[inline-changes.json](inline-changes.json)은 소스 안 문구 4개다.
[scope.json](scope.json)에 기준 스냅샷·파일 범위·문맥 검토 결과를 기록했다.
[app-copy.patch](app-copy.patch)는 **이번 차수의 차이만** 담고 있다.
이전 문구 개선 전체나 TTL-Work의 다른 UI 수정은 포함하지 않는다.

패치는 이 차수 시작 시점의 미커밋 파일을 기준으로 만들었다. 앞선 차수의 검사 코드가
없는 main에 그대로 적용되지 않을 수 있다. 테스트 패치의 기준 부분은 이번에 추가한
맨 앞 테스트 블록만 제거해 재구성했다. 파일 전체를 이 세션 소유라고 해석하지 않는다.

1. 사용자 요청, 현재 브랜치, 공통 소유권 기록, [앞선 차수](../copy-handoff.md)를 읽는다.
2. 현재 구현과 변경 전후 값을 대조한다. 이미 반영된 것은 다시 바꾸지 않는다.
3. 자신의 워크트리에서 패치 적용 가능 여부를 확인한다.

```powershell
git apply --check docs/session-start/multilingual-copy-260906/app-copy.patch
```

4. 전제 코드가 다르면 필요한 변경만 현재 구현에 맞춰 옮긴다. 검사 완화를 위한
   일괄 allowlist, 다른 세션의 전체 파일 덮어쓰기, 공용 main 편집을 하지 않는다.
5. 문구·화면 연결·검사 사례를 함께 검증하고 적용한 범위와 외부 반영 여부를 기록한다.

이번 실행 결과는 [checks.json](checks.json), 사용자용 결과는
[완료 보고](completion-report.html)에 기록한다. 테스트 원본·화면 캡처·수정 전 스냅샷은
`E:\2ndB\.worktrees\2ndB\TTL-Work\Output\multilingual-copy-260906`에 있다.
이 경로가 없으면 검증 결과를 새로 실행했다고 주장하지 않는다.

- 3개 언어의 11,301개 문자열에서 효능·임상 서비스 표현 후보를 검색했다.
  `tratamiento/tratamento` 2건은 데이터 처리 설명이라 유지했다. 문자열 검색은
  원어민 전수 교정이나 모든 위험 표현의 탐지를 뜻하지 않는다.
- ES/PT/ID의 안전·동의 안내는 승인된 기존 영어 사본을 유지한다. 정형 설문·동의 체크문을

  일부 빈 데이터 fixture로 수행한다. 런타임 답변 언어·유료 기능 검증과 구분한다.

  초안의 ES는 중남미, PT는 브라질 표현이다. 출시 국가와 콘솔 언어는 별도로 확인한다.

`COPY-INTEGRATE-260906`에서 이 차수도 함께 확인한다. 앱 반영과 문서 보존, 스토어
