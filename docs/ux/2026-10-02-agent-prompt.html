# 작업 지시서: 2nd-Brain UI 톤앤매너 전면 개편 ("합쇼체 설명 + 해요체 질문" 결합 모델)

## 1. 배경 및 Simon의 핵심 제품 철학
현재 2nd-Brain 앱 전반의 한국어 UI 카피와 세컨비(SecondB) 대화 어조가 지나치게 차갑고 "연구용 AI 시스템 감사관"처럼 느껴집니다.
- **Simon의 제품 철학 (2026-08-17)**: "사용자와 소통해서 깊게 파악하고, 그를 기반으로 심리상담(친구 같은)·개인 비서 역할을 하게 하는 것."
- **주의 (C1 하드 제약)**: 임상 용어("심리상담", "치료", "우울증", "진단" 등)는 의료법상 UI 텍스트에 사용이 엄격히 금지됩니다(`scripts/check-forbidden-lexicon.ts`). 단, **기능 자체는 제약이 없으므로** "친구처럼 깊게 듣고 파악하는 다정하고 편안한 페이스메이커" 톤을 구현해야 합니다.

## 2. 톤앤매너 핵심 공식 (Simon 확정 원칙)
1. **황금 표현 공식**:
   `[객관적 사실·분석 데이터 안내: 단정한 합쇼체 (~합니다 / ~입니다)] + [사용자 생각 묻기·제안: 다정한 해요체 (~어떤가요?, ~해볼까요?)]`
   - *모범 예시*: `"000은 000합니다. [이름]님은 어떤가요?"`
2. **영문 번역투 '당신' 전면 배제**:
   - `당신` → `{{who}}님` (동적 사용자명) 또는 주어 생략 (`"어떤 생각이 드시나요?"`, `"어떻게 생각하세요?"`)
3. **엔지니어링·아키텍처 어휘 정제**:
   - `주간 리즈닝 횟수` → `주간 심층 분석 횟수`
   - `이 페르소나 승인 (Ratify)` → `이 모습으로 담기`
   - `페르소나 제안 받기` → `기록으로 나의 모습 정리하기`
   - `AI 연결 제안` → `관련된 기록 찾아보기`
   - `L1~L5` 등 내부 모델 계층 표현 노출 제거
4. **차가운 방어적 면책문(Disclaimer)을 따뜻한 대화형 제안으로 전환**:
   - As-Is: `"AI가 추정한 결과예요. 나와 맞는지 확인해 주세요."`
   - To-Be: `"남겨주신 기록들을 토대로 정리한 나의 모습입니다. {{who}}님이 느끼는 내 모습과 잘 맞나요?"`
   - As-Is: `"최근 80개만 읽었어요. 점수가 아니에요."`
   - To-Be: `"최근 남겨주신 80개의 기록을 바탕으로 분석했습니다. 요즘 내 일상과 가장 가까운 영역은 어디인가요?"`

💡 핵심 톤앤매너 설계 원리

합쇼체 (~합니다 / ~입니다) 객관적 사실 · 데이터 집계 · 시스템 상태
+
해요체 (~어떤가요? / ~해볼까요?) 사용자 생각 묻기 · 다정한 제안 · 질문
=
친구 같은 개인 비서 신뢰성 + 친근감 완벽 밸런스
1. 신뢰감과 권위 (합쇼체 영역)

"최근 80개의 기록을 분석했습니다", "이번 주 루틴 달성률은 78%입니다." 처럼 앱이 데이터를 집계하고 상태를 전달할 때는 단정한 격식체로 신뢰감을 부여합니다.

2. 심리적 연결과 질문 (해요체 영역)

"{{who}}님은 이 분석에 대해 어떻게 생각하세요?", "오늘 저녁 가볍게 회고해볼까요?" 처럼 사용자의 마음에 말을 건네어 대화형 성찰(Reflective Dialogue)을 유도합니다.

⚠️ 새 에이전트가 흔히 빠지는 함정 (CI Failure 방지)

1. 임상 금지어 스캔 (`check:lexicon`): '심리상담'이라는 단어를 UI에 쓰면 CI가 즉시 깨집니다. 단어 대신 '깊은 대화', '되돌아보기', '마음 정리' 등의 표현을 사용해야 합니다.
2. 마스코트 보이스 (`check:mascot-voice`): Wall 2 키는 반드시 사용자 발화를 유도하는 물음표(?)로 끝나거나 기록이라는 단어가 포함되어야 합니다.
3. 시스템 프롬프트 테스트 (`identity-prompt.test.ts`): conversation.ts 수정 시 ~습니다, ~나요?, 개인 매니저 키워드가 빠지면 테스트가 실패합니다.
