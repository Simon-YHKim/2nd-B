네보리 · 동행자

사용자를 가장 잘 아는 기본 형태. 둥근 보라 구름과 안정된 중앙 코어가 기준이다.

메타리 · 관찰자

기록을 한 걸음 떨어져 비추는 형태. 얼굴 주변에 얇은 청록 관찰 프레임이 생긴다.

  • 주색 #46B6FF
  • 코어 좌우 1px 대괄호형 빛
  • 진폭이 가장 작은 움직임
twi → twiri

트위리 · 발상자

새 관점과 아이디어를 펼치는 형태. 우상향 혜성 가지와 따뜻한 점광 하나가 열린 방향을 만든다.

  • 주색 #CFC4E8
  • 보조점 #F5E6BE
  • 좌우 확장 펄스 1-2px
키 안정성: 저장 데이터와 API의 내부 키 secondb, meta, twi는 1차 통합에서 유지한다. 표시 이름만 KO 네보리·메타리·트위리, EN Nebori·Metari·Twiri로 바꿔 데이터 이관을 피한다.
개념 경계: 네보리·메타리·트위리는 채팅에서 사고 방식을 바꾸는 form이다. Layer C 북극성이 합성하는 사용자의 persona 역할·모자와는 다른 축이며, 세 form을 사용자 성격이나 별자리 노드로 저장하지 않는다.

05 · Polaris-linked growth

북극성이 밝아질수록 별에 가까워진다

성장 입력은 (await loadDomainLevels(userId)).northStarBrightness만 사용한다. 호환 구간의 표시 상태 프로퍼티가 soulCoreBrightness라는 이름을 유지하더라도 값을 계산할 때 stars.ts::soulCoreBrightness()를 호출하면 안 된다. 성장 단계는 홈 도메인에서 축적된 정보의 선명도를 보여준다.

L1 · 먼지

코어 1-2px. 눈 없음. 실루엣은 조각난 구름 3개 이하.

L2 · 응집

코어가 생기고 눈 두 개가 처음 보인다. 몸은 아직 불완전하다.

L3 · 형성

현재 샘플 단계. 네보리의 고정 실루엣과 세 형태 서명이 읽힌다.

L4 · 정렬

코어 가장자리에 4방향 별빛이 1-2px 생긴다. 북극성과 더 가까운 위치로 이동한다.

L5 · 동반성

작은 동반성처럼 북극성 궤도에 놓인다. 여전히 북극성 시각 직경·광도의 60% 이하.

표시 단계northStarBrightness 구간진입 규칙
L1[0.20, 0.40)초기값은 clamp(floor(brightness × 5), 1, 5). 직전 표시 단계를 저장하고 0.40·0.60·0.80 경계의 상·하향 임계에 ±0.02 hysteresis를 적용한다. L5는 정확히 1.00에서 진입하고 0.98 미만에서 이탈한다.

L3[0.60, 0.80)

성장 단계 간 형태 보존 규칙
  • L1-L2도 같은 비대칭 방향과 코어 좌표를 사용한다.
  • L3-L5는 외곽을 새로 그리는 것이 아니라 같은 실루엣을 응축·정렬한다.
  • L4의 4방향 빛은 북극성의 예고 신호이며 완전한 별 모양 외곽이 아니다.
  • L5에서도 네보리는 홈의 탐색 노드가 아니며 탭 가능한 도메인 별처럼 보이면 실패다.
  • L1-L4의 cyan guide는 성장 방향을 암시하는 안내선일 뿐 궤도가 아니다. 실제 궤도 배치는 L5에서만 허용한다.
  • 60% 상한은 전체 전신 박스가 아니라 같은 좌표계의 발광 코어 직경과 효과 halo 직경에 각각 적용한다. 현재 북극성 core 18k, halo 34k 기준으로 네보리는 각각 10.8k, 20.4k 이하다.
  • 감소·회귀 연출은 사용하지 않는다. 데이터 수정 시 단계가 내려가더라도 부드러운 상태 교체만 한다.

시선 추적: 픽셀 네보리는 연속 pointer/touch tracking을 하지 않는다. 직접 누른 순간에만 시선을 1 native px 이동하는 단발 반응은 허용한다. 추적 루프와 센서는 만들지 않으며, reduced motion에서는 이 반응도 생략한다.
정보 밀도: 한 화면에서 캐릭터는 한 곳에만 크게 보인다. 별자리 화면은 북극성이 유일한 hero이며 네보리는 작은 머리형으로 물러난다. 채팅은 헤더 머리형, 북극성이 없는 전용 장면은 전신형이 주 그래픽이다. 선택기에 세 개의 큰 캐릭터를 동시에 넣지 않는다.

Android 메모리·렌더링 예산
  • 192×192 RGBA 한 장의 decoded memory는 약 144KiB다.
  • hero @4x 384×384 RGBA 한 프레임은 약 576KiB다. 동시에 decoded 상태인 sheet는 현재 form과 전환 대상 form, 최대 2장으로 제한하고 합계 3MiB 이하를 지킨다.
  • 가로 sheet의 최대 변은 2048px 이하, sheet 한 장 decoded 1.5MiB 이하를 목표로 한다.
  • 기존 1250px급 머리 PNG를 형태별·단계별로 복제하지 않는다. 한 장이 약 6MiB decoded가 될 수 있다.
  • expo-image의 local asset에 cachePolicy="memory"를 사용한다. 대상 form은 전환 직전에 lazy-load하고 morph가 끝나면 이전 form sheet 참조를 해제한다.
  • fractional scaling 대신 실제 LOD·density 파일을 선택한다.
  • SVG filter, node-heavy SVG, bitmap 내부 blur, base64 AsyncStorage 저장을 금지한다.
  • 광원 번짐은 캐릭터 PNG 밖의 별도 View 레이어에서 만든다. sprite viewport의 overflow: hidden과 광원 레이어를 분리한다.
  • 화면 blur·unmount·AppState background에서 루프·타이머·애니메이션을 모두 정리한다.
