## 3. 기록 표 · 쓰는 주체

### 3.1 누가 무엇을 알 수 있나

| `verdict` | text | `credited` · `none` · `other_layer` · `no_verdict` · `error` (프록시가 계산) |
| `opener_unedited` | boolean | 답이 직전 말문 후보와 같은가(클라이언트) |
| `answer_len_bucket` | smallint | 글자 수 구간(0-4 · 5-7 · 8-13 · 14+), 원문 없음 |
| `created_at` | timestamptz | |

- 원문 · 해시는 **넣지 않습니다.** 해시는 감사 행에 이미 있습니다.
- 클라이언트 역할 권한 0, RLS FORCE. 읽기는 집계 뷰(service_role)로만.
- 삭제: 계정 삭제 cascade(0198 등록부에 등록), '데이터만 삭제'에서도 지움(인터뷰 기록과 같은 콘텐츠로 봄, 추론).

**`interview_coverage` (0143) 변경**

- `authenticated` 의 INSERT · UPDATE 회수는 **0220 이 아니라 그 다음 번호**로 미룹니다(6절 이유). 0220 은 `answers` 를 줄이는 UPDATE 를 막는 BEFORE UPDATE 트리거만 넣습니다(R2F-12 보강 (3) 첫 항목).
- 새 함수 `commit_interview_session(p_session_id)`(SECURITY DEFINER, `authenticated` 실행): 세션이 호출자 소유인지(프록시가 JWT 로 묶어 둔 세션) 확인 → 그 세션에서 `verdict='credited'` 이고 `local_gate='pass'` 인 행을 (period, layer, scene_seq) 로 묶어 **장면마다 층당 최대 1** 만큼 `answers = answers + 1` 로 더함 → 같은 세션은 한 번만(`committed_at`). 두 기기 동시 저장도 원자적 증가라 증분을 잃지 않습니다(LAST-04 해소).
