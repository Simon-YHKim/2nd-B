## 상태 계약

| 실제 결과 | 처리 | `InterviewTurn.answered` | 물었던 층의 실패 횟수 |
|---|---|---|---|
| 안전한 성공 응답, 같은 층 판정 | 로컬 관문도 통과했다면 물었던 층만 인정 | `true` | 기존 성공 처리 |
| 안전한 성공 응답, 판정 없음 (`undefined`) | 로컬 관문대로 물었던 층 인정 | `true` | 기존 성공 처리 |
| 명시적 `none` (`null` in ProbeResult) | 불인정, 기존 발판/소진 규칙 | `false` | 기존대로 증가 |
| 다른 유효 층 이름 | 중립, 어떤 층도 인정하지 않음 | `null` | 이전 값 유지 |
| 요청 오류 | 오류 안내, 같은 층에서 재시도 | `undefined`, `unsettled:true` | 불인정으로 추가하지 않음 |
| 입력/출력 위기 | 기존 안내·종료, coverage 증가 없음 | 판정 처리에 진입하지 않음 | 판정 처리에 진입하지 않음 |

ProbeResult의 null(명시적 none)과 InterviewTurn의 null(완료된 중립 결과)은 서로 다른
타입의 값이다. screen은 파서가 돌려준 유효한 다른 층을 중립으로 변환한다.
그 상태를 boolean으로 접거나, `== null`로 판정 전과 합치지 않는다.
scene 진전은 `answered === true`만, 실패는 `=== false`만, 현재 판정 대기는
`=== undefined && !unsettled`만 센다. 중립값을 저장/복원할 때도 null 그대로 유지한다.

## 다음 질문과 실패 횟수

한 모델 호출은 직전 답의 판정과 다음 질문을 함께 만든다. 화면은 그 답이 인정된다고
가정하고 다음 층을 고르므로, 다른 층 판정이 오면 그 질문과 말문 후보를 사용할 수 없다.
현재 층에서 아직 쓰지 않은 기존 고정 대체 질문을 `usableQuestion`으로 고른다.
후보를 모두 썼다면 새 질문을 중복 추가하거나 자동 종료하지 않고, 마지막 질문과
전체 대화를 그대로 두고 같은 층의 입력을 받는다. 응답마다 모델을 다시 부르지 않는다.
사용자는 기존 건너뛰기·사실만·여기까지 선택을 계속 쓸 수 있다.

send가 잠시 0으로 둔 실패 횟수는 중립 결과일 때 요청 전 값으로 돌린다. 따라서
none 두 번 → 다른 층 → none은 여전히 세 번째 명시적 실패에서 기존 규칙대로 끝난다.
다른 층을 성공으로 치거나 실패 횟수를 초기화하여 발판 한도를 우회하지 않는다.
중립 판정을 실패/종료로 바꾸지 않는 것은 Q5를 구현하는 데 필요한 부분이며,
T31의 새로운 장면 선택을 먼저 넣는 것이 아니다.

기존 ‘장면 판정 호출 15회’는 다른 층도 실패로 세던 구현을 전제했다. 이제 그 상한은
인정/명시적 불인정에 해당한다. 다른 층 중립·통신 오류는 별도로 세고 기존 서버 예산과
사용자의 명시적 보내기 경계를 유지한다. 새 클라이언트 횟수 상한을 발명하지 않는다.
