# 북극성 밝기 조회의 확인된 입력

T43의 읽지 못한 값을 정상 빈 값으로 표시하지 않는 범위다. 기존 밝기 계산식·비준 승격·
프로필을 제외한 여섯 평균과 태그 출처 정책은 바꾸지 않는다. T54의 출처 이주는 별도다.

`loadSevenLevelsStrict`는 coverage, profile, 목표 문장, 동료 응답, 비준 이력 다섯 입력을
확인한 뒤 기존 순수 계산 함수를 사용한다. 각 요청의 오류와 잘못된 응답은 다른 요청이
멈춰 있어도 실패하며, 입력이 전부 정상 빈 결과인 경우만 기존 L1을 계산한다.

strict 조회는 캐시와 in-flight 공유를 사용하지 않는다. 기존 profile reader가 오류를
L1로 계산한 뒤 45초 캐시에 저장하더라도 여기에는 들어오지 않는다. 기존 생성·인터뷰·홈의
fail-soft reader와 writer는 수정하지 않았다. `/me/<star>` strict reader의 입력 정책과
순수 계산을 참조했지만 해당 화면의 별도 count/경로 계약을 변경하지 않기 위해 reader를
추출하거나 일곱 번 호출하지 않았다. 알려진 coverage의 잘못된 count는 실패하고 미래의
시기/층 key는 기존과 같이 무시한다. 이 호환 정책은 비어 있지 않은 문자열 식별자가 실제로
반환된 경우에만 적용한다. period/layer/star_id 누락이나 잘못된 타입은 실패하며 정상 L1로
처리하지 않는다. 최신 비준 행이 우선하고 낮은 비준값이 계산값을 내리지 않는다.

필수 scope callback을 실제 dispatch 차례, 응답 후 및 최종 반환 전에 검사한다. 이 함수는
이미 보낸 네트워크의 취소나 고정 JWT를 보장하지 않는다. 화면 연결 단위가 owner/epoch/focus,
10초 한도, 개별 재시도와 QA 자동 실행 권한 무효화를 제공해야 한다. 현재 화면 caller는 없다.

검사는 실제 새 reader와 기존 legacy reader를 실행하고 Supabase 응답만 대역으로 둔다.
정상 결과 동등성, 각 입력 실패·hang·malformed, cached 실패 L1과 진행 중 legacy 요청의
분리, 요청 owner/filter, 늦은 owner 변경을 검증한다. 독립 검토·전체 검증·CI와 실제 화면
연결 전에는 이 준비를 T43 완료로 세지 않는다.
