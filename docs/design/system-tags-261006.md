## 4. `domain:` 태그

- **`tags` 에 둡니다**(#2094 판단 유지). 근거:
  1. 쓰기 경로가 정해진 DomainId 만 씁니다 — `withDomainTag`(`src/lib/records/detect-domain.ts:129`), `stripDomainTags`(`src/lib/persona/domain-stars.ts:80`), 상세 화면 거부(`dds-record-detail-screen.tsx:591`).
  2. 사용자 자신의 분류입니다(Move 로 바꿉니다). "어떻게 만들어졌나"가 아니라 "어디에 두었나"입니다.
  3. 읽는 곳이 많습니다(#2094 본문 "읽는 곳 전수": 별 밝기 · `/star/[domain]` · 커리어 타임라인 · 대시보드 · 상세 Move 등). 옮길 이득은 0 이고 비용만 큽니다.
- `system_tags` 의 모양 제약은 `domain:` 을 거부합니다(`0218:138-150`). 유지합니다.
- 게이트가 남긴 단서(astra r1): "어느 쓰기 경로로도 못 들어온다"는 UI 경로에 한정됩니다. 소유자 API 로는 임의의 `domain:*` 를 쓸 수 있습니다(`updateRecordTags` 에 서버 제한 없음). 영향은 자기 별 밝기뿐이라 이 설계에서는 막지 않습니다. 서버에서 DomainId 목록을 강제하는 일은 옛 행 검사와 엮여 별도 작업입니다.

## 5. 옛 APK 정책

| 사실 | 근거 |
|---|---|
| 스토어에 나간 적 없음 | `0218:111` · #2094 본문 |
| 설치본은 QA 로 깐 APK 뿐 | #2094 본문 "영향은 QA 로 깐 APK" (설치 대수는 세지 않음, 추론) |
| 실사용자 인터뷰 기록 0 | 1.3 |
| 옛 판을 막거나 업데이트를 강제하는 장치 없음 | `0218:106-109` (`notices.min_app_version` 은 공지를 고르는 조건일 뿐) |
| main 머지마다 APK 를 자동으로 만듦 | `.github/workflows/android-release.yml:37-39` (`push: main`) |

정책:

1. 옛 판을 위한 호환 읽기를 만들지 않습니다. 표식을 `tags` 에 다시 겹쳐 두는 것이 곧 이 마이그레이션이 없애려는 결함입니다.
2. **적용 완료 조건 = 웹 게시 + QA APK 교체**(머지 뒤 android-release 가 만든 APK 로 QA 설치본을 바꿈). 에뮬레이터 · adb 는 Simon 이 다시 허락할 때까지 쓰지 않으므로, 교체는 Simon 폰에서 하고 그 사실을 기록합니다.
3. 적용과 교체 사이에 옛 판이 새로 쓴 기록(표식이 `tags` 에 있음)은 6.2 의 6단계 사후 집계로 찾아, 같은 손 이행으로 옮기거나 그대로 둡니다(QA 데이터).
4. 옛 판 차단 장치(최소 판 검사)는 이 설계 범위 밖입니다. 출시 뒤 같은 종류의 칸 이동이 또 생기면 그때 필요해집니다.

칸이 있는 DB 에서 옛 판이 쓴 행(`system_tags` 가 비고 표식이 `tags` 에 있음)은 새 앱이 인터뷰 · TTFV 로 알아보지 못합니다. 그 행은 6단계 집계가 찾습니다.

### 6.2 운영 적용 순서 (모두 GO 대상)

1. 구현 PR(draft)이 게이트를 통과할 때까지 머지하지 않습니다.
2. **적용 직전 읽기 집계**: 후보 행 수 · 계정별 행 수 · 계정이 QA · 제작자 계정인지. 결과를 Simon 에게 보이고 손 이행 대상(행 번호 목록)을 확정합니다. 실사용자 행이 있으면 그 행은 목록에서 빼고 그대로 둡니다.
3. **0218 적용**: 칸 · 모양 제약 · 북극성 두 함수. 데이터는 바꾸지 않습니다.
4. **손 이행 SQL**(같은 GO, 별도 트랜잭션): 우회 역할 확인 → `row_security=off` → 목록의 행마다 지금 `tags` 가 2단계에서 본 값과 같은지 확인(다르면 그 행은 건너뜀) → 표식만 `system_tags` 로 → 사후 집계. 행 번호 · 전후 값은 저장소 밖 보고서 폴더에만 두고, DECISIONS 에는 개수와 목록 해시만 적습니다.
5. PR 머지 → 웹 게시(publish 디스패치) → android-release 가 APK 를 만듦 → QA 설치본 교체.
6. **사후 집계**: 3단계 뒤에 만들어진 인터뷰 · TTFV 행 중 표식이 `tags` 에 남은 행 = 옛 판이 쓴 행. 0 이 아니면 4단계를 그 행에 한 번 더(주인 확인 뒤).

창: 3~5단계 사이에는 옛 웹 · 옛 APK 가 `tags` 만 읽으므로, 4단계에서 옮긴 QA 행이 옛 판에서는 인터뷰로 보이지 않습니다. 영향은 QA 계정뿐이고, 북극성 생성은 운영에서 꺼져 있습니다.

## 7. 마이그레이션 0218 개요

| 부분 | 내용 | #2094 대비 |
|---|---|---|
| ① 칸 | `records.system_tags text[] NOT NULL DEFAULT '{}'` + COMMENT | 같음(`0218:128-132`) |

계정 · 내용 삭제와 내보내기: 칸은 `records` 행의 일부라 행과 함께 지워지고(0189 `client_erasable`), 계정 내보내기는 `select('*')` 라 새 칸이 그대로 실립니다(#2094 본문, astra r1 동의 · 개인정보 축).
