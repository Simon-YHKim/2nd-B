## 무엇이 틀렸나

리즈닝 화면은 사용량을 목록과 한 번에 `getReasoningUsage` 로 읽었다. 그 함수는 자동 실행 · 홈 · 한도 시트를 위해 **일부러 실패를 0 으로 바꾼다**(fail open). 그래서 화면은 다음을 확인된 숫자처럼 보였다(2026-10-16 baseline 재현 7건).

1. 카운터 오류 → 「주 2회 남음」.
2. 두 번 쓰고 원장 오류 → 「소진」.
3. 원장 숫자가 문자열 → 「소진」.
4. 카운터는 바로 오류, 원장은 무응답 → 목록 기한 10초까지 기다림.
5. 확인된 1회 사용 뒤 새로 고침 오류 → 가짜 「2회 남음」.
6. 새로 고침 무응답 → 옛 숫자를 계속 현재 값처럼 보임.
7. 계정 A 의 늦은 새로 고침 → 계정 B 의 숫자를 덮음.

### 수명과 소유

- 결과는 (계정, 계정 세대, 포커스 세션, 요청 번호)가 모두 같을 때만 보인다.
- 계정 전환 구독이 다시 그리기 전에 읽기를 끊고, 읽는 동안의 확인(`assertCurrent`)이 lease 를 본다. 둘은 같은 경우를 두 겹으로 막는다(하나만 지워도 시험이 통과하는 이유 · 둘 다 지우면 「다시 그리기 전 끊기」 시험이 실패한다).
- `refresh` 는 **확정된 계정 세대**(보류가 아닌 게시된 lease 의 epoch)마다 같은 함수다. 그래서 복구 효과(`[refreshUsage, userId]`)가 새로 고침 · 재시도 · 포커스 · 보류 때문에 다시 돌지 않는다(같은 계정이 보류에서 돌아와 새 세대가 확정되면 한 번). 옛 세대(A → B → A, 중간 렌더가 없어도)의 함수는 자기 epoch 를 새 lease 와 대조해 거절된다.
- 「확인됨」 결과에는 확인 토큰이 붙는다. 새로 고침 · 화면 떠남 · 계정 전환 · 언마운트 · 새 읽기 시작이 그 토큰을 **동기적으로** 지우고, 실행 버튼은 누르는 순간 `confirmCurrent`(토큰 + 세션 + lease)로 다시 확인한다. 그래서 이전 렌더의 버튼을 쥔 채 위 사건 뒤에 눌러도 실행이 시작되지 않는다(독립 검토 1회차 high). 확인 함수는 **그 렌더가 보여 준 바로 그 토큰 객체**에 묶여서, 뒤에 새 「확인됨」이 실려도(새로 고침이 2/2 소진을 확인 · 다시 포커스 · A → B → A 복귀) 옛 버튼을 다시 허가하지 않는다(2회차 high).

### 북극성: main과 달라지는 실패 정책 (검토 1회차 고침)

대조 기준 `origin/main`(`d83afa8751eb`)의 북극성은 처음에 사용 0·크레딧 0으로 시작한다. `getReasoningUsage`는
카운터 실패·예외면 그 0을 돌려주지만, 원장만 실패하면 읽힌 카운터와 월 미러를 사용한다.
따라서 원장만 실패한 소진 사용자는 /plans로 가고, 카운터 실패 사용자는 화면 내 로컬
증가분으로 한도까지 허용된다. 모든 실패를 0회 남음으로 읽어 막았던 것은 아니다.

이번 변경은 **확인값 없는 첫 대기·실패에서 제안을 막으므로 main보다 엄격하다**.
원장만 실패해도 공용 엄격 조회는 거절한다. 읽기 재시도는 제안·차감 기록을 호출하지 않는다.
이미 확인된 값이 있으면 오류·시간 초과에도 그 값과 이후 성공한 제안 수를 유지한다.
주 기본뿐 아니라 보상 크레딧을 사용한 제안도 총 잔여 횟수에서 하나씩 뺀다. 이 값은 한도
판정용이며 화면에 숫자로 표시하지 않는다. 현재 세대의 확인값 없는 상태를 0으로 채우지 않는다.

기록 요청을 기다리지 않고 제안 버튼을 돌려주되, 진행 중인 기록이 있으면 중간 재조회가 로컬
증가분을 지우지 못한다. 기록 완료 후 새 확인값이 오면 교체하며 두 번 차감하지 않는다.
오래된 버튼도 누르는 순간 최신 로컬 횟수를 보고, 계정·세대가 바뀌면 이전 값을 폐기한다.
검토자 재현(확인된 1회 → 제안 → 기록 완료 → 재조회 대기/실패 → 제안)은
고치기 전 제안 2회·/plans 0회, 고친 뒤 제안 1회·/plans 1회다. 시간 초과도 같은 판정이다.

요금제의 효과 실행 전 투영은 별도 실행 시험으로 고정한다. 소유자·epoch·유효 lease 중
하나라도 다르면 이전 숫자를 숨기므로, A → B → A 복귀 직후 효과 실행 전 프레임도 포함한다.
