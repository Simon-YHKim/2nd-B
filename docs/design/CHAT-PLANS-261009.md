# 대화에서 루틴·리마인더 제안

Simon 요청, 2026-10-09: 입력창 위의 위키 담기 버튼과 함께 루틴이나 리마인더로 만들 만한 내용을 제안한다.

- 최신 완료 대화에서 사용자의 구체적인 반복 의도는 `루틴으로 만들기`, 한 번 할 일과 날짜·알림 요청은 `리마인더 만들기`로 제안한다.
- 로컬 규칙으로 판단한다. 추가 LLM 호출이나 자동 저장은 없다. 인사, 거절, 취소한 일, 과거의 일, 안전 안내 응답에서는 제안하지 않는다.
- 위키 담기가 필요한 대화에서는 기존처럼 위키가 첫 번째다. 루틴·리마인더는 그다음, 일반 후속 질문은 그 뒤에 놓는다.
- 버튼은 확인 시트를 연다. 제목·반복·요일·분류·시간을 고친 뒤 확정한다. 불명확한 날짜와 시각은 비워 두고 사용자에게 맡긴다.
- 루틴은 기존 `ops_routines`에 저장하여 개인 비서의 루틴 목록과 오늘 할 일에서 재사용한다. 주간 루틴은 알림 시간을 정하지 않아도 요일을 보존한다.
- 폰의 일회성 리마인더는 계정별 암호화 기기 저장소에 제목과 정확한 시각을 보존하고 기존 기기 알림을 예약한다. 리마인더 화면에서 내용을 다시 보고 알림을 끄거나 삭제할 수 있다. 지난 일정을 임의로 내일로 옮기지 않는다.
- 알림 권한은 확정 이후에만 요청한다. 저장 후 알림 권한이 거부되면 저장 성공과 알림 실패를 구분하여 알려 중복 저장을 막는다. 잠금화면에는 기존의 일반 문구만 표시하며, 알림을 누르면 현재 계정에 속한 저장 항목인지 확인한 뒤 리마인더 목록을 연다.
- 웹에서는 기기 알림을 예약하지 않는다. 사용자가 내보내기에 동의하면 편집한 제목·날짜·시간으로 캘린더 파일을 만든다. 브라우저에서 알림이 예약됐다고 표시하지 않는다.
- 계정 변경·대화 초기화·전송 중·옛 제안은 확인 단계에서 다시 검사한다. 중복 탭은 하나의 저장만 실행하고, 성공한 제안은 해당 대화에서 다시 노출하지 않는다.

검증 대상: 대화 제안 정책, 날짜·시각 검증, 저장과 권한 실패의 분리, 계정 전환, 확인 시트, 모바일 화면 및 폰 안의 동일 화면.

세션: `HUSTLEK-CHAT-ALIGN-261009`. 같은 변경에서 내 메시지의 아바타를 오른쪽, 닉네임을 왼쪽에 정렬한다.
