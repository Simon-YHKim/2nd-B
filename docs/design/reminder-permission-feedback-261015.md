# T41 · 알림 권한 거부 안내와 명시적 설정 열기

2026-10-15 · 구현 기준 `decdda9b6d332d626aee76e0b41674ca31a8a5a8` · 제품 축: 개인 비서 기반.

## 상충과 우선순위

1. O1은 권한을 거절하면 스위치가 이유 없이 꺼져 있는 관찰이고, Z55는 거절 뒤 설명 없이 시스템 설정으로 넘어가는 관찰이다. 거절 안내를 먼저 보여 주고 **별도의 설정 열기 탭**만 `Linking.openSettings()`를 실행하게 한다. 거절을 자동 설정 이동이나 자동 재예약의 동의로 해석하지 않는다.
2. [10-13 결정 기록 42행](../../DECISIONS-2026-10-13.md#L42)은 Z55를 “새 문구라 시안부터”로 남겼다. 이번에는 기존 `secondb:planSuggestion.reminderDenied`와 `secondb:chatSaveNoticeOpen`을 다섯 언어 그대로 재사용한다. 아래 전·후 시안은 배치 설명이며 실제 앱 캡처나 기기 완료 증거가 아니다. 기존 승인 문구의 뜻을 바꾸지 않는다.
3. 단순히 모든 실패에 권한 안내를 붙이면 저장·예약 오류를 권한 거부라고 오인시킨다. 반환값을 구분하고, 취소 실패 때는 켜진 스위치를 그대로 유지한다. 계정 전환·화면 종료 뒤의 응답은 표시하지 않는다.

## 근거와 실제 진입점

- [10-07~12 기록 291행](../../DECISIONS-2026-10-07_12.md#L291): O1 원관찰. 이전 기기 시험에서 예약·취소가 성공했다는 기록은 이번 수정의 기기 시험이 아니다.
- [같은 기록 298·300행](../../DECISIONS-2026-10-07_12.md#L298): 남은 작업 진행 지시와 원문 복구, O1·O2 처리 범위. 이후 전체 남은 작업 완수 지시 안에서 준비하며 새로운 출시·스토어·운영 권한을 만들지 않는다.
- [`src/app/reminders.tsx`](../../src/app/reminders.tsx): 로그인 계정의 `RemindersScreen`을 `key={userId}`로 연다.
- [`PhoneOpsContent.tsx`](../../src/screens/deepspace/ops/PhoneOpsContent.tsx): 휴대전화 안의 같은 알림 화면을 연결한다.
- [`screens.tsx`](../../src/screens/deepspace/ops/screens.tsx): `RemindersScreen` → `ReminderCard` → 권한 거부 때만 `ReminderPermissionSettings`.
- [`reminders.ts`](../../src/lib/ops/reminders.ts): 기기 권한·계정 소유권·로컬 예약과 취소. 알림 제목·본문의 개인정보 보호 문구는 변경하지 않는다.

## 전·후 시안

| 상태 | 변경 전 | 변경 후 |
|---|---|---|
| 켜기를 눌렀지만 권한 거부 | OFF만 남고 다음 행동이 보이지 않음 | OFF 유지 + 기존 거부 안내 + `설정 열기` |
| 설정 열기 | 이 화면에는 연결된 버튼 없음 | 직접 누른 때만 OS 설정을 열고, 돌아온 뒤 다시 켜기 탭으로 예약 |
| 저장·예약 실패 | 모두 거부처럼 취급되지만 이유를 렌더하지 않음 | 일반 오류 문구, 설정 버튼 없음 |
| 지원되지 않는 환경 | 알림 토글 없음 | 기존 지원 여부 유지. 지원 확인 이후 실행 중 unavailable이면 기존 기기 안내 |
| 재시도 성공 | ON | ON + 이전 거부 안내와 설정 버튼 제거 |
| 실제 취소 실패 | 기본 취소 함수가 실패를 삼키면 OFF로 표시할 수 있음 | 이 화면만 strict 취소, 실패 시 ON 유지 + 일반 오류 |
| 계정 변경·오래된 응답·화면 종료 | 명시적 응답 세대 보호 없음 | 현재 계정 lease와 화면 생명주기로 결과·설정 호출 차단 |

```text
전                                   후 · 권한 거부
물 마시기             [OFF]          물 마시기             [OFF]
매일 09:00 · 개인 비서                매일 09:00 · 개인 비서
                                     알림 권한이 꺼져 있습니다.
                                     설정에서 허용한 뒤 다시 시도해 주세요.
                                     [설정 열기]
```

위 샘플은 합성 루틴이며 실제 사용자 자료가 아니다. 앱은 기존 줄 너비에 따라 안내를 감싸고, 안내가 있는 독립 화면 카드는 OFF 불투명도 저하를 적용하지 않는다. 휴대전화 안과 밖의 기존 카드·스위치·버튼을 재사용하며 새 모달은 없다. 안내에는 `accessibilityRole="alert"`, `accessibilityLiveRegion="polite"`를 적용한다.

인수 HTML: `t41-reminder-permission-before-after.html`(세션 첨부). 한국어·영어·스페인어·포르투갈어·인도네시아어, 권한 거부·예약 오류·성공·취소 실패, 밝은/어두운 테마를 선택할 수 있다. 문구 원본은 이 저장소의 `locales/{ko,en,es,pt,id}/secondb.json`과 `common.json`이며 HTML이 별도 문구 정본이 되지는 않는다. 저장소에는 이 표와 문자열 키를 남겨 첨부 없이도 다음 검토자가 수정 범위를 복구할 수 있게 한다.

## 구현 계약

- `enableReminderWithResult`: `enabled | denied | unavailable | error | stale`. 기존 `enableReminder`와 `ensureNotificationPermission`의 boolean API를 유지한다.
- 권한 거부는 권한 응답으로만 판정한다. 저장소·예약 실패는 `error`, 계정 lease가 바뀌면 `stale`이다. stale은 이전 계정의 행을 표시하거나 켜지 않는다.
- 같은 계정 세대와 루틴의 실행 중인 탭은 한 번만 처리한다. 재시도 시작 시 이전 안내를 지운다.
- `disableReminder`는 기존 호출의 best-effort 동작을 유지하고, 선택적 `{ strict: true }`를 이 화면에서만 전달한다. 실제 OS 취소 실패를 삼키지 않게 해야 화면의 catch와 ON 유지가 작동한다. 실패 시 영속 비활성 요청과 실제 예약이 다를 수 있으며 기존 잔여 예약 정리 경로가 재시도한다. 전체 취소 저장 설계를 바꾼 수정은 아니다.
- Settings 버튼은 계정 세대·소유권·mounted를 다시 확인한다. 열기 실패는 일반 오류로 알린다. 설정을 열었다고 권한 허용이나 예약 성공을 표시하지 않는다.
- OS 알림 문구·예약 시간·계정 정리 정책·동의·언어 파일·네이티브 의존성·DB·LLM 경로는 변경하지 않는다.

## 코드 검사와 한계

- 기존 12 suites를 `--runTestsByPath`로 명시하여 **264 tests PASS**. 패턴 `reminder`만 주면 워크트리 경로에도 맞아 전체 suite가 선택되므로 사용하지 않는다.
- 신규 화면 검사는 실제 소스에서 `reminderSchedule`, `ReminderCard`, `ReminderPermissionSettings`, `RemindersScreen`을 TypeScript AST로 추출하여 실행한다. JSX·OS 호출과 hook 수명은 시험 장치이며 Android 렌더러가 아니다. 거절 안내/명시 탭, 오류 구분, 중복 탭, 재시도, 취소 실패, 계정 pre-transition/ABA, settings 실패, unmount 뒤 응답/설정 호출을 검사한다.
- 라이브러리 검사는 실제 구현과 알림 SDK 모의 응답으로 최종 거절·첫 프롬프트 거절·권한 조회 실패·저장 실패·예약 직전 권한 철회·예약 실패·계정 변경 및 strict 취소 실패 전달을 확인한다. 화면의 reject mock만으로 실제 실패 전파를 입증하지 않는다.
- 타입 검사와 변경 TypeScript 4파일 ESLint PASS. 전체 `npm run verify`와 독립 검토는 별도 슬롯에서 최종 HEAD에 수행한다. 이 문서는 그 검사가 이미 끝났다고 주장하지 않는다.
- HTML 시안은 headless Chromium에서 밝은/어두운 캡처를 확인했다. 360·390 폭 × 5언어 × 4상태, 총 40조합에서 가로 넘침 0과 안내·버튼·ON/OFF 분기 및 시안 버튼 응답을 확인했다. 이 수치는 HTML에만 적용되며 실제 화면의 레이아웃 검사 수치가 아니다.
- 실제 앱 화면 캡처, Android의 설정 왕복·권한 재허용·알림 예약, 8081 반영·앱 parity는 미확인이다. HTML 시안 확인과 단위 검사로 대신 완료 처리하지 않는다. 모델 호출·운영 변경·알림 실제 발송은 0이다.

## 남은 기기 확인

최종 병합 빌드에서 권한 최초 거절/두 번 거절 후 OFF 안내 → 명시 Settings 탭 → 복귀 → 다시 켜기 → 실제 예약 1개를 확인한다. 설정에서 허용하지 않고 돌아왔을 때, 저장·예약·취소 실패, 연속 탭, 계정 전환, 화면 이탈 중 늦은 응답도 확인한다. 휴대전화 안/독립 `/reminders`, 360·390 폭, 큰 글꼴, 다섯 언어와 화면 낭독에서 안내와 버튼 잘림을 점검한다. 시험 예약은 마친 뒤 취소하고 실제 예약 목록이 비었는지 확인한다.
