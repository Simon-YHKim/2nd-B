# records 의미 색인 (D5) — 동의 · 백필 · 비용

> 작성 2026-08-31 (REQ-260901-02). 코드 정본: `src/lib/records/records-embeddings.ts` ·
> 화면: `src/screens/deepspace/DeepSpaceDesignScreens.tsx` (privacy → "기록 의미 연결").

## 무엇

`records`(일지·노트 — 가장 민감한 말뭉치)를 의미 벡터로 색인해 "연결된 기록" 을 보여주는 층.
모델 호출은 전부 LLM 경계(`embedTexts`, C1/C3/C9/Cost)를 지난다.

## 동의 게이트 — 전부 여기서 갈린다

- **기본 OFF.** `records_embedding`(privacy pref, `src/lib/privacy/prefs.ts`)을 성인이 명시적으로
  켜야 한다. `recordsEmbeddingAllowed()`는 모델 호출 전 앱 검사이며, 최종 DB 저장과는 시차가 있다.
- **미성년은 삼중으로 막힌다** — 화면 가드(`isMinor` 조기 반환) · 서버(0072 트리거가 `minor_self` 의
  pref 를 강제 false) · 그리고 백필의 `stillConsented` 프로브가 **저장된 서버 값**을 매 라운드
  다시 읽으므로, 트리거가 방금 저장한 pref 를 조용히 false 로 되돌렸다면 1라운드 전에 멈춘다.
  **클램프에 우회·완화·특례 없음** (Simon 명시, 2026-08-31).
- **서버 삭제로 전환 준비(0263).** 설치 뒤에는 허용→불허 변경과 vector·`embedding_model`
  삭제가 같은 트랜잭션이고, 늦은 쓰기도 잠금 뒤 현재 동의·성인 여부로 판정한다.
  운영 적용·기존 잔여 정리는 아직 별도다. [Relay 인수와 앱 전환 조건](ops/records-embedding-consent-0263.md).
  현재 화면과 백필은 `clearRecordEmbeddings` 직접 호출을 유지한다.
- **명시적 켜기만 CAS 표식을 보낸다.** 앱은 저장된 판본의 다음 값을 보내고 실제 ON 응답을
  확인한다. 0263은 철회 시 판본을 올려 옛 true 저장·늦은 켜기 요청의 재동의를 막는다.
  표식 앱을 먼저 머지·게시하고 0263을 나중에 적용한다. 옛 앱은 적용 뒤 새로 켜지 못한다.

## 색인을 만드는 손 — 둘

| 경로 | 언제 | 코드 |
|---|---|---|
| 쓰기 시점 | 기록을 담는 순간 (detached) | `create.ts` → `embedAndStoreRecord` |
| **동의 시점 백필** | pref 가 **false → true** 로 바뀌는 순간 (detached) | `enableEmbedding()` → `backfillAllRecordEmbeddings` |

**동의 시점 백필은 Simon 결정 (a) (2026-08-31, REQ-260901-02)** — "records 백필은 (a) 동의를
켤 때 기존 기록도 일괄 색인하는 쪽으로 간다. 0072 미성년 클램프는 그대로 지킬 것."
동의 화면 문구도 같은 PR 에서 "지금까지 담아 둔 기록과 앞으로 담는 기록"으로 고쳤다 —
이전에 밖으로 나가지 않던 텍스트가 나가기 시작하는 변경이라, 문구가 범위를 정확히 말해야
동의가 근거로 성립한다.

⚠ **이 변경 이전에 이미 켜 둔 사용자**(운영 실측 1명, 17건 중 1건만 색인)는 백필을 받은 적이
없다 — 트리거가 "false → true 전환" 뿐이기 때문이다. 그 계정은 토글 off → on 한 번이면 전량
색인된다. 그래서 "켜져 있어요" 상태 문구는 소급 색인을 단정하지 않는다(동의 전 문구만 범위를
말한다).

## 끄기와의 경합 — detached 배치가 정직함을 지키는 방법

배치는 수 초 이상 걸릴 수 있고 그동안 사용자는 "끄고 벡터 삭제"를 누를 수 있다.
`stillConsented`(서버 pref 프로브)가 그 창을 닫는다:

1. **매 라운드 전** 프로브 — OFF 가 저장돼 있으면 즉시 중단(`aborted`).
2. **루프 종료 후** 프로브 — 그 시점에 OFF 면, 사용자의 clear **이후에** 이 배치가 저장한
   벡터가 있을 수 있으므로 **배치가 스스로 `clearRecordEmbeddings` 를 한 번 더** 돌린다
   (`cleared`). 라운드는 순차 await 라 마지막 저장이 끝난 뒤에 이 확인이 돈다.

이 앱 정리는 best-effort라 요청 실패·종료·늦은 쓰기까지 막지는 못한다.
0263 설치 뒤 성공한 철회와 이후 불허 상태의 쓰기는 서버가 처리한다. 기존 잔여는 별도 정리한다.
다시 켠 뒤 늦게 온 직접 NULL 삭제는 서버가 현재 ON의 완전한 쌍을 유지한다.
오래된 false 전체 객체는 철회로 처리하는 기존 동작이 남는다. 잘못된 저장 판본은
OFF·서버 판본으로 복구하며 삭제하고, 새 CAS로만 다시 켤 수 있다.
`storeRecordEmbedding`은 실제 반환 행이 정확히 하나이고 저장된 모델이 맞아야 true다.
서버가 비웠거나 RLS·삭제 경합으로 0행이면 단건·백필 모두 저장 성공으로 세지 않는다.

## 부분 실패 · 감사 · 재시도

- 백필은 **detached·best-effort** 다. 어떤 실패도 방금 저장된 동의를 되돌리지 않는다.
- 위기(red-zone) 텍스트는 C9 이 배치에서 제외한다(제로 벡터, **저장 안 함**) — NULL 로 남는다.
- 배치 전체가 실패하면(프록시 422/5xx 등) **행 단위로 재시도**해 무고한 행을 건진다
  (`embedAndStoreRecord`, 동의 인자 전달 — 리뷰가 잡은 5번째 인자 누락 수정됨).
- **감사(정밀하게):** mock 모드는 배치당 클라이언트 행 1개. 라이브(엣지)는 **프록시가** 자기
  행을 남기고, red-zone 텍스트가 섞인 배치는 클라이언트 위기 행이 더해질 수 있다. **실패한
  프록시 호출은 텍스트가 이미 나갔어도 클라이언트 행이 안 남을 수 있다** — 원장은 성공의
  기록이지 시도의 완전한 기록이 아니다. 행 단위 폴백은 각 호출이 자기 감사 행을 남긴다.
- **재시도 경로 = 토글 off → on.** off 가 벡터를 지우니 on 이 **처음부터 전량을 다시** 만든다
  (멱등, 단 전량 재-egress — 아래 비용).

## 비용 가드

- 배치 50건 = `embedTexts` 1콜. 한 번의 토글당 **최대 10라운드(500건)** 에서 멈춘다(`maxRounds`).
- `capped: true` 는 **"이번 실행은 여기까지"이지 이월이 아니다** — off → on 은 삭제 후 최신부터
  재시작이라, 500건 넘게 쌓인 사용자는 지금 구조로는 꼬리를 영영 색인하지 못하고 재시도마다
  같은 최신 500건을 다시 지불한다. **그런 사용자가 나타나면 서버측 배치로 옮겨야 한다**
  (현재 최대 보유 사용자 138건 — 도달까지 여유 있음). 각 실행은
  `[records-embedding] backfill …` 로 라운드·건수·중단 사유를 로그에 남긴다.
- 현재 규모(2026-08-31): 전체 158건 NULL ≈ 콜 4회. **사용자가 늘면 "동의 토글 1회"가
  그 사용자의 기록 수에 비례하는 비용을 갖는다.**
- 페이지네이션은 `created_at` 키셋(`before` 커서)이라, 색인 안 되는 행(red-zone·빈 텍스트)이
  최신 페이지를 점유해도 그 뒤의 오래된 행에 도달한다.
