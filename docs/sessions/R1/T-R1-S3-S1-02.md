## "Gemini로 안 감" 근거 — 측정값이 LLM에 안 들어감 (CONFIRMED)

1. 읽기 경로: "No network, no LLM, $0" — src/lib/health/sources/health-connect.ts:10-11.
2. ingest: 결정론적, no LLM — src/lib/health/ingest.ts:11 (자동완료도 규칙표 기반, no LLM).
3. health_samples 소비자는 딱 둘:
   - src/lib/persona/load-domain-levels.ts:116-121 — select("source").limit(1) 만 읽는다. 건강 도메인 레벨에 "기기 소스 존재" 1비트로만 기여. 걸음/심박수 등 값 자체는 읽지 않음.
   - src/lib/ops/routines.ts (applyHealthAutoComplete) — 결정론적 루틴 자동완료, no LLM.
4. health_samples 는 wiki 스냅샷(daily-brief/chat 의 LLM 컨텍스트)에 포함되지 않음 (grep 확인).

결론: 걸음·운동·수면·심박수 측정값은 어떤 LLM 프롬프트에도 들어가지 않는다. (파생 '레벨' 숫자 자체가 persona/gap LLM 콜에 들어가는지는 S2 배선 영역이지만, 건강의 기여분은 존재 1비트뿐이라 측정값 노출은 0. 선언 문구는 "측정값 미전송"으로 안전하다.)

## S1/Simon 결정 필요 (추측하지 않고 비워서 돌려보냄)

1. READ_HEART_RATE 실사용이 사실상 없다. 심박수 값은 루틴·AI·값기반 레벨 어디에도 쓰이지 않고 저장 + 존재비트뿐이다. Play 는 "쓰지 않는 데이터 권한 요청"을 반려 사유로 본다. -> (a) "심박수 기록 저장/표시" 용도로 정직하게 선언하거나 (b) 실사용이 없으면 app.json 에서 READ_HEART_RATE 를 제거하는 안을 검토. 히스토리 화면 표시 여부는 S2 확인 요망(listRecentSamples 소비처).
2. S3 이전 오보 철회. 예전에 "채널 C = Apple Health export.xml 이 본문 그대로 LLM 으로 간다"고 보고했으나 틀렸다. src/lib/import/health-export.ts:7-8 은 "no network, no LLM, no storage; 파생 요약만 저장"이다. verbatim 아님. 또한 그건 iOS/파일 업로드 경로라 이 Android 선언과 무관하다. (임의 파일/캡처 import -> wiki -> LLM 일반 경로는 별개이니 S5 와 재검증 권장.)
