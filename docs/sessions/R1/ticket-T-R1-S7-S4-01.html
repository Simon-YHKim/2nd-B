왜 이걸 했나Why this was done

홈 화면의 북극성 밝기 계산이 틀려 있었다. 보이지도 않는 항목까지 평균에 넣어서, 사용자가 보는 별 여섯 개는 어두운데 북극성만 밝아지는 일이 있었다. 그걸 고친 코드가 어제 합쳐졌다. 그런데 이미 만들어진 앱 설치본은 옛날 코드를 들고 있으므로, 고친 부분을 무선으로 밀어 넣어야 새 화면이 나온다. 그 작업을 했다. 그리고 그 밀어넣기가 엉뚱한 사람의 앱까지 바꾸지 않는지를, 앱 파일을 직접 열어서 확인했다.

The home screen's "north star" brightness was computed wrongly — it averaged in items the user cannot see, so the north star could brighten while all six visible stars stayed dark. The fix was merged yesterday. But an app that is already built carries the old code, so the fix has to be pushed over the air before the new screen appears. That push is done. And I opened the app file itself to confirm the push cannot land on anyone else's install.

#1141(Polaris 6도메인 consumer)이 main에 들어갔지만, 설치된 바이너리는 JS 번들을 갱신받기 전까지 이전 화면을 그린다. S4가 /(home) 촬영을 STOP한 이유가 그것이다. production 채널 OTA가 그 잠금을 푸는 단 하나의 조치였고, 그 전제인 runtime 격리를 추정이 아니라 아티팩트로 확인해야 했다.

#1141 landed on main, but an installed binary keeps rendering the old screen until its JS bundle updates. That is why S4 held the home capture. A production-channel OTA was the single action that releases the hold — provided runtime isolation holds, which had to be verified from the artifact rather than assumed.
