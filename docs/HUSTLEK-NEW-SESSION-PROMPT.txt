HustleK 픽셀 에셋 작업을 새 세션에서 이어간다.

작업 대상 worktree는 E:/2ndB/.worktrees/hustlek-imagegen-pilot 이다.
E:/2ndB canonical main checkout이나 다른 worktree에서 파일을 수정하지 마라.
먼저 위 경로를 작업 디렉터리로 사용하고 실제 branch를 확인해라.

작업 전에 다음 파일을 순서대로 끝까지 읽어라.

1. docs/HUSTLEK-PIXEL-ASSET-GUIDE.md
2. docs/HUSTLEK-SESSION-HANDOFF.md
3. 같은 worktree에 존재하면 SESSION_RECOVERY.md
4. docs/HUSTLEK-COMPOSITION.md
5. animation 작업인 경우에만 docs/HUSTLEK-OPENING.md

이 파일들과 저장소의 실제 hash·manifest가 채팅 기억이나 자동 요약보다 우선한다.
SESSION_RECOVERY.md와 durable handoff가 다르면 timestamp와 실제 저장소 상태를 대조하고,
그 차이를 첫 응답에서 보고해라.
Pixy skill, Pixy CLI, .pix, pixy.spec.json은 사용하지 마라.

첫 응답에서는 아직 이미지를 생성하거나 파일을 수정하지 말고 다음만 보고해라.

- repo root, worktree, branch, HEAD
- git status의 clean/dirty 상태
- catalog의 ready_for_review와 approved 수
- 승인된 style-lock id·경로·decoded RGBA hash 또는 “없음”
- handoff 파일에 기록된 마지막 완료 지점
- 이번 세션에서 수행할 정확히 하나의 atomic task

보고 내용과 저장소 상태가 다르면 작업을 시작하지 말고 차이를 먼저 설명해라.

제작 규칙:

- 원본 저해상도 에셋은 identity와 silhouette reference일 뿐이다.
- 저해상도 픽셀을 확대해 128px master로 사용하지 마라.
- 고정된 사용자 승인 style lock 없이 bulk 생성하지 마라.
- reference 이미지는 batch 도중 교체하지 말고, 직전 생성 결과를 다음 reference로 이어 쓰지 마라.
- canonical master는 진짜 native-detail 128×128 RGBA로 먼저 제작한다.
- 한 세션에는 한 asset family만 다룬다.
- style-lock 단계에서는 대표 asset 1개만 생성하고 사용자 승인을 기다린다.
- production 단계에서도 새 128px master는 한 세션당 최대 4개다.
- 하나가 반려되거나 style drift가 발견되면 같은 세션의 추가 생성을 중단한다.
- 16·32·48·64px는 승인된 128 master에서 Pillow NEAREST로 각각 직접 파생한다.
- 크기별 독립 생성과 128→64→32→16 연쇄 축소를 금지한다.
- plain NEAREST가 identity baseline이다.
- semantic cue 소실이 증명된 target pixel만 좌표 whitelist로 최소 보정한다.
- 수정하지 않은 픽셀은 baseline과 byte-identical해야 한다.
- 모든 production PNG는 binary alpha이고 transparent pixel의 hidden RGB는 0이어야 한다.
- source, prompt, style reference, builder, master, tier, correction plan의 hash를 기록한다.
- 모든 검증이 PASS하기 전에 승인 파일이나 catalog를 덮어쓰지 마라.

Context Guard:

- context 사용량 70%부터 새 batch를 시작하지 말고 SESSION_RECOVERY.md 초안을 갱신한다.
- 80%부터 새 ImageGen 호출과 새 master 제작을 중단한다.
- 90%에서는 read-only 상태 확인, 검증 결과 기록, 인계만 수행한다.
- 자동 compaction이 발생하면 정확한 수치와 관계없이 80% 이상으로 간주한다.
- context 수치가 보이지 않더라도 style drift, 규칙 재탐색, 기억 의존, 동일 실패 반복이 나타나면 즉시 같은 중단 규칙을 적용한다.
- 중단 시 현재 atomic unit의 검증·commit만 안전하게 끝내고 SESSION_RECOVERY.md를 갱신한다.
- 종료 전 최종 사실을 docs/HUSTLEK-SESSION-HANDOFF.md에도 반영해 commit한다.
- 그 뒤 사용자에게 새 세션을 권장하고 이 prompt 파일을 다시 제공한다.

현재 handoff의 “새 세션의 정확한 다음 작업”만 수행해라.
완료된 이전 작업을 다시 만들지 말고, 사용자가 새 범위를 명시하지 않는 한 다음 단계로 확장하지 마라.
