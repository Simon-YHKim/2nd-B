# HustleK Opening Asset and Animation Contract

이 문서는 `HustleK and opening` 시퀀스의 제작 정본이다. 다른 Codex 세션이나 AI는 새 이미지를 추측해서 만들지 말고, 이 문서와 커밋된 atlas를 사용해 동일한 캐릭터와 165프레임 애니메이션을 재생성해야 한다.

## 1. 정본과 우선순위

충돌이 생기면 다음 순서를 따른다.

1. `design/hustlek-opening-v1/hustlek-opening-atlas.png`의 승인된 픽셀
2. 이 문서의 좌표, 타임라인, 금지 규칙
3. `scripts/build-hustlek-opening.py`의 결정적 합성 로직
4. `design/hustlek-opening-v1/hustlek-opening-preview.gif`의 육안 검토본

GIF는 128색 검토본이다. 픽셀 정본은 atlas이며, 전체 165프레임 정본은 스크립트가 생성하는 APNG다.

## 2. 빠른 재생성

필수 조건:

- Python 3.11 이상
- Pillow 12.2.0
- Pillow 설치가 끝난 뒤의 렌더 자체는 네트워크 연결 불필요
- Pixy, image generation, 외부 visualization 폴더 불필요

`uv`가 있으면 다음 명령을 권장한다.

```powershell
uv run --with Pillow==12.2.0 scripts/build-hustlek-opening.py
```

일반 Python 환경에서는 다음과 같이 실행한다.

```powershell
python -m pip install Pillow==12.2.0
python scripts/build-hustlek-opening.py
```

기본 산출물 위치는 gitignored `Output/hustlek-opening/`이다. 다른 경로가 필요하면 다음처럼 지정한다.

```powershell
python scripts/build-hustlek-opening.py --output C:\temp\hustlek-opening
```

성공 조건은 프로세스 종료 코드 `0`과 `validation.json`의 `status: "PASS"`다.

## 3. 고정 제작 규격

| 항목 | 정본 값 |
|---|---:|
| 화면 | 640×360 RGB |
| 세로 월드 | 640×640 RGBA |
| 전체 프레임 | 165 |
| 프레임 시간 | 80ms |
| 전체 길이 | 13,200ms |
| 캐릭터 셀 | 96×96 RGBA |
| 캐릭터 기준 높이 | 87px |
| 머리 꼭대기 | local y=7 |
| 발바닥 기준선 | local y=94 |
| 망원경 셀 | 128×128 RGBA |
| 지면 | world y=592 |
| 정북축 | world/screen x=320 |
| 카메라 X | 항상 0 |
| 카메라 Y | 280에서 52 |
| 북극성 월드 중심 | (320, 232) |

여기서 “32px”는 사용자가 승인한 단순한 픽셀 RPG 감성의 밀도를 뜻한다. 실제 제작 셀은 캐릭터 비율과 애니메이션의 일관성을 위해 96×96을 사용한다. 32×32로 다시 축소하거나 프레임마다 다른 배율로 정규화하지 않는다.

## 4. Atlas 계약

파일: `design/hustlek-opening-v1/hustlek-opening-atlas.png`

- 형식: RGBA PNG
- 크기: 640×776
- 리샘플링: 없음
- 빈 영역: 완전 투명

| 영역 | 좌표 `(left, top, right, bottom)` | 규격 |
|---|---|---|
| 승인 배경 | `(0, 0, 640, 360)` | 1장, 640×360 |
| 보행 01–06 | `(0, 360, 576, 456)` | 6셀, 각 96×96 |
| 보행 07–12 | `(0, 456, 576, 552)` | 6셀, 각 96×96 |
| 회전·접안 키포즈 01–06 | `(0, 552, 576, 648)` | 6셀, 각 96×96 |
| 북향 망원경 | `(0, 648, 128, 776)` | 1셀, 128×128 |

셀 순서는 왼쪽에서 오른쪽이다. 보행은 첫째 줄 01–06, 둘째 줄 07–12다. 키포즈는 다음 순서다.

1. 정측면 정지
2. 대각 후면
3. 후면 정지
4. 후면에서 팔을 절반 올림
5. 접안 직전
6. 접안 완료

Atlas 무결성 기준:

```text
PNG SHA-256:
2780df89aa6f1d472ec82a03610a6d7e81a20dbf9e767103cd198233e44213be

Decoded RGBA SHA-256:
b077a2d1a4c77c320e92a18b92a722f4a2905340e7b1ba27c47d6a0cf2c8cc49
```

파일 메타데이터나 압축 옵션 때문에 PNG 파일 해시는 달라질 수 있다. 실제 픽셀 동일성은 decoded RGBA 해시로 판단한다.

승인된 165개 RGB 프레임을 순서대로 이어 붙인 픽셀 스트림 해시는 다음과 같다.

```text
be712f383b207d0de5508f485481aa41d8fe8769b087220993a357342780ff33
```

스크립트는 생성 직후 APNG를 다시 디코딩해 이 해시와 비교한다. 따라서 컨테이너 압축이 달라도 화면 픽셀이 승인본과 같음을 확인할 수 있다.

## 5. 허슬케이 스타일 잠금

허슬케이는 다음 특징을 모든 방향과 프레임에서 유지한다.

- 큰 머리와 작은 몸의 치비 비율
- 좌우가 비대칭인 짙은 가르마 머리와 따뜻한 좌상단 하이라이트
- 얼굴에서 가장 먼저 읽히는 크고 둥근 검은 안경
- 박시한 흰색 반팔 티셔츠
- 발목까지 이어지는 카키색 긴 바지와 검은 벨트
- 황갈색 레이스업 워크부츠, 높은 발목과 어두운 밑창
- 좌상단 광원
- 선택적인 짙은 외곽선과 제한된 명암 단계

다음은 금지한다.

- 다른 게임이나 제3자 sprite를 추출하거나 덧그리기
- 승인된 캐릭터를 prompt만으로 재생성하기
- 프레임별 독립 확대·축소
- bilinear, bicubic, LANCZOS, 안티앨리어싱, 블러
- 그라데이션이나 디더링을 캐릭터에 추가하기
- 머리, 안경, 몸통, 바지, 부츠의 부피를 프레임마다 변경하기
- 카키 바지를 반바지처럼 줄이기
- 부츠를 얇은 단화나 작은 갈색 점으로 축약하기
- Pixy skill, Pixy CLI, `.pix`, `pixy.spec.json` 사용

수정이 꼭 필요하면 atlas의 해당 셀을 정수 좌표에서 직접 고치고, 나머지 셀은 그대로 둔다. 새 생성 결과로 atlas 전체를 교체하지 않는다.

## 6. 애니메이션 규칙

### 6.1 보행

- 보행은 12프레임, 프레임당 80ms다.
- 팔과 다리는 서로 반대 위상으로 흔든다.
- 위치가 변하는 동안에는 실제 보행 포즈만 사용한다.
- 정지, 회전, 접안 포즈를 x축으로 평행 이동하지 않는다.
- 지지발은 지면에 붙고, 이동발은 passing에서 지면과 분리되어야 한다.
- 상체는 다리 변화와 함께 최대 1–2px 범위에서 움직인다.

접근 마지막 구간의 정확한 매핑은 다음과 같다.

| 프레임 | 에셋 | 중심 X |
|---:|---|---:|
| 59 | walk 07 | 263 |
| 60 | walk 08 | 273 |
| 61 | walk 09 | 283 |
| 62 | walk 10 | 293 |
| 63 | walk 11 | 302 |
| 64 | walk 12 | 310 |
| 65 | walk 01 | 316 |
| 66 | walk 02 | 320 |

이 값은 보행 속도를 자연스럽게 줄이면서 망원경 앞에서 멈추게 한다.

### 6.2 90도 회전과 접안

회전은 모든 중간 각도를 그리지 않는다. 다음 세 방향만 hold한다.

| 프레임 | 방향/행동 | 중심 X |
|---:|---|---:|
| 67 | 측면 정지 | 320 |
| 68–69 | 대각 후면 | 320 |
| 70–72 | 후면 정지 | 320 |
| 73 | 팔 절반 올림 | 320 |
| 74 | 접안 직전 | 320 |
| 75 이후 | 접안 완료 | 320 |

회전 키 사이를 보간하지 않는다. 세 자세의 명확한 전환이 로봇처럼 잘게 회전하는 것보다 자연스럽다. 후면 기본 몸체를 고정하고 73–75에서는 팔과 손의 접안 동작만 바꾼다.

### 6.3 망원경

- 북쪽을 보는 후면 망원경 한 장만 사용한다.
- world 위치는 항상 `(256, 468)`이다.
- 크기, 회전, 삼각대 폭, 광축을 프레임마다 바꾸지 않는다.
- 캐릭터 전환 셀에 망원경을 다시 구워 넣지 않는다.
- 캐릭터가 망원경 앞을 지나는 가림만 허용한다.

### 6.4 카메라와 북극성

- 북극성 X와 망원경 광축은 모두 `x=320`이다.
- 카메라가 지상 장면을 보여 줄 때 북극성은 화면 바깥에 있어야 한다.
- 9,000ms부터 카메라 Y만 `280 → 52`로 이동한다.
- 카메라 X 이동은 0이다.
- 북극성은 별도 fade-in으로 등장하지 않는다. 월드 좌표에 고정된 채 카메라 이동으로 위쪽에서 들어온다.
- 북극성은 가로·세로 팔 두께가 같고 90도 회전 대칭이어야 한다.
- 11,600–12,300ms에 한 번만 반짝인다.

## 7. 전체 타임라인

| 구간 | 시간 | 내용 |
|---|---:|---|
| 0 | 0–800ms | 검은 화면에서 fade in |
| 1 | 800–2,200ms | 초원과 고정 망원경 |
| 2 | 2,200–4,800ms | 허슬케이 보행 진입과 감속 |
| 3 | 4,800–7,200ms | 최종 접근 보행, 측면·대각·후면 회전과 접안 준비 |
| 4 | 7,200–9,000ms | 망원경 관측 hold |
| 5 | 9,000–11,600ms | 카메라가 하늘로 이동해 북극성에 초점 |
| 6 | 11,600–12,300ms | 북극성 한 번 반짝임 |
| 7 | 12,300–13,200ms | 검은 화면으로 fade out |

## 8. 레이어 순서

각 프레임은 다음 순서로 합성한다.

1. 640×640 세로 배경 월드
2. 고정 망원경
3. 해당 시점의 허슬케이 보행 또는 키포즈
4. 북극성과 반짝임
5. 640×360 카메라 crop
6. 화면 공간의 검은 fade

망원경은 항상 한 번만 합성한다. 카메라 팬 동안 배경, 망원경, 캐릭터, 북극성은 같은 월드 카메라를 공유하고, 검은 fade만 화면 공간에서 처리한다.

## 9. 필수 검증 게이트

`validation.json`은 최소한 다음을 모두 통과해야 한다.

- atlas 크기와 decoded RGBA 해시 일치
- 640×360, 165프레임, 80ms, 총 13,200ms
- APNG 디코딩 프레임 165개
- GIF 총 재생 시간 13,200ms
- APNG decoded RGB frame stream이 승인 해시와 일치
- 첫 프레임과 마지막 프레임이 완전한 검은색
- 승인 배경의 하단 360px가 픽셀 단위로 동일
- 정북축 `x=320`, 카메라 X 이동 0
- 팬 전 북극성이 완전히 화면 밖
- 북극성 90도 회전 대칭
- 키포즈 6개 모두 96×96, 바닥 anchor y=94
- 키포즈 신장 편차 최대 1px
- F59가 walk 07로 이어짐
- F67 이후 캐릭터 중심 X가 모두 320
- 측면·대각·후면 3단계 회전 매핑 일치
- 고정 망원경 레이어 1개
- Pixy 관련 파일과 호출 0개

육안 검토도 생략하지 않는다.

1. 전체 GIF를 정상 속도로 한 번 본다.
2. F55–80을 1×에서 확인한다.
3. 같은 구간을 nearest-neighbor 4×로 확인한다.
4. F58→59, F66→67, F74→75에서 크기·발바닥·중심축 pop을 확인한다.
5. 걷는 동안 발 미끄러짐과 팔 고정을 확인한다.
6. 망원경이 작아지거나 두 번 그려지는지 확인한다.

## 10. 실패 사례와 복구

| 증상 | 원인 | 복구 |
|---|---|---|
| 서 있는 채 미끄러짐 | 정지/회전 pose에 x 이동 적용 | 이동 구간을 walk pose로 되돌림 |
| F67부터 체격 변화 | 서로 다른 board를 개별 정규화 | 공통 96×96 atlas와 공통 scale 사용 |
| 로봇 같은 회전 | 각도를 너무 많은 중간 pose로 보간 | 측면·대각·후면 3단계로 복구 |
| 망원경 크기 pop | 캐릭터 pose에 망원경을 함께 합성 | 고정 망원경 단일 레이어로 복구 |

| 팬 전에 별이 보임 | screen 좌표로 별을 합성 | world `(320,232)`에 두고 camera crop 사용 |

## 12. 프로비넌스

- 캐릭터 방향은 사용자가 제공한 인물 사진과 승인 피드백을 바탕으로 이 프로젝트를 위해 생성했다.
- 원본 인물 사진은 저장소나 atlas에 포함하지 않는다.
- 캐릭터, 배경, 망원경은 이 프로젝트 작업 기간에 생성된 결과를 Pillow로 정규화·합성했다.
- 다른 게임에서 추출한 sprite나 제3자 asset pack을 사용하지 않았다.
- atlas와 preview는 Pixy를 사용하지 않았다.
- 생성 과정과 저장소 등록 내역은 `docs/ASSETS.md`에 함께 기록한다.
