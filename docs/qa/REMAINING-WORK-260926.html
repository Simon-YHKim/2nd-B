서버 선행 적용의 순서

서버 선행 적용은 사용자가 승인했습니다. SESSION-OWNERSHIP에 따라 운영 DB·Edge·시크릿·플래그는 별도 콘솔 세션 소유입니다. 이 세션은 콘솔 담당 수락을 확인하지 못했고 운영 쓰기를 하지 않았습니다. 초안 8개는 번호 예약과 db/erasure-registry.json forward additions 및 rollback/0189_down.sql의 registry-only 반영 전이므로 현재 HEAD 그대로 전체 ledger 왕복을 통과한다고 주장할 수 없습니다.

남은 작업과 완료 조건
  1. 콘솔 담당: 원장·함수 서명/ACL·표·Edge 버전·설정 존재를 운영에서 읽고 번호를 예약한다. 격리 clone에서 통합 SQL·등록부·rollback·CLI ledger 왕복을 통과시킨다.
  2. 콘솔 담당: Reward/Paddle을 기능별 OFF·drain한 뒤 DB와 고정 소스 Edge를 적용한다. 서비스 동의 collect coverage와 canary, Paddle sandbox, Reward SSV 검증 후에만 해당 기능을 연다.
  3. 코딩 세션: 가입 RPC와 이메일 확인의 정확한 게시 가드, 서버 coverage/canary 확인 뒤 클라이언트 공개를 결정한다. 실제 Android 로그인·카메라·오디오, 실모델 인용 품질, GA4 전송도 남는다.
  4. Grok 후속: 이전 사용자 보류 지시를 유지하고 별도 재개 답변을 기다린다. 기존 전달 영수증의 nonce를 중복 전송하지 않는다.
