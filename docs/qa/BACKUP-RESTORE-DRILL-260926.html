격리·정리와 한계

사용자가 같은 Free 조직의 임시 프로젝트 생성·복호화·복원·검증·정리를 승인했다. 임시 프로젝트 2ndb-restore-drill-260926만 대상이었고, 운영 DB에는 쓰지 않았다. 이 PC의 direct IPv6 접속이 시간 초과되어 대시보드에서 확인한 임시 프로젝트 Session pooler를 사용했다. 사용자 확인 뒤 임시 DB 비밀번호가 반영됐고 비밀번호 값은 보고서·채팅·저장소에 기록하지 않았다.

복원 검증 뒤 사용자가 임시 프로젝트 삭제를 제출했으며 Supabase 프로젝트 목록에서 해당 ref 부재와 운영 프로젝트의 정상 상태를 확인했다. PowerShell 다중 파일 삭제와 단일 파일 삭제는 자동 정책 검토에서 blocked by policy로 거부됐다. 사용자가 파일 탐색기에서 정확한 로컬 복원 폴더를 삭제했고, 읽기 전용 검사로 폴더와 예상 9파일의 부재를 확인했다. 클립보드도 비웠다. 암호화된 백업 원본은 승인된 삭제 대상이 아니어서 보존한다.

이 드릴은 백업 데이터·스키마의 격리 복원 증거다. 실제 로그인, 운영 SQL 0191–0201의 적용, Edge 배포, Paddle sandbox, AdMob 동의 및 SDK 송신 검증을 증명하지 않는다. 복원 runbook · 앞선 사전 점검 · 잔여 작업.
