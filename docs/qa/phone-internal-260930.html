변경 근거와 구현
화면 경계기존 아이콘이 독립 라우트로 빠져나가던 경로를 내부 화면 스택으로 바꿨다. 독립 진입 화면과 별자리 메인은 수정하지 않았다.
대시보드 첫 화면첫 화면 위의 큰 배너를 앱 목록에만 남겨, 첫 행동 카드가 작은 화면에서 먼저 보이도록 했다. 요약·근거의 순서를 유지한다.
뒤로가기와 종료내부 뒤로가기·Android Back·하단 홈 버튼은 내부 화면을 정리한다. 핸드폰 루트의 종료 버튼은 확인 단계를 거친다. 루트에서 아래로 스와이프하면 종료하고, 하위 화면에서는 한 단계 뒤로 간다.
자료 상태최근 기록·루틴·건강 자료의 실제 값, 자료 없음, 읽기 실패를 분리한다. 전체 읽기 실패 시 이전 성공 자료를 최신인 것처럼 표시하지 않는다.
실제 화면에서 발견한 오류일반 기록 상세의 제목이 ‘인터뷰 원문 열기’였던 것을 ‘기록 보기’로 고쳤다. 회귀 테스트를 먼저 실패시킨 뒤 수정하고, QA 계정 화면에서 문구를 재확인했다.
안전핸드폰 안의 짧은 메모 저장은 기존 기록 생성·위기 분류 경로를 사용하고, 위험 응답은 안전 안내로 연결한다.
검증 매트릭스
375px · 425px 프레임통과: fitPhoneArtwork 단위 테스트 및 실제 375×812·425×747 스크린샷. 원본 프레임 전체와 내부 도크가 모두 보인다.
내부 이동·뒤로가기QA 계정에서 앱→집중 타이머, 앱→리마인더→하단 노트, 하단 검색→기록 상세를 클릭했다. URL은 계속 /2nd-B/dashboard였다. 내부 뒤로가기는 한 단계씩 돌아갔다.
아래 스와이프·종료브라우저 창에서 아래로 드래그했다. 집중 타이머에서는 앱 목록으로 돌아갔고, 루트에서는 핸드폰을 닫았다. 물리 홈 버튼은 바로 종료하지 않고 확인 화면을 보여주며 ‘계속 보기’로 취소됐다. 루트 종료 후 QA 계정은 앱의 기존 IntroGate에 의해 /2nd-B/onboarding으로 이동했다.
접근성브라우저 접근성 트리에서 앱 아이콘, 내부 뒤로가기, 검색 입력, 하단 버튼, 종료 확인 선택지가 역할·이름으로 노출됐다. 스크린리더 실기는 미수행.
빈 상태·읽기 실패리마인더의 ‘오늘 예정된 루틴이 없어요’ 빈 상태와 최근 기록 14건의 실데이터 표시를 QA 계정에서 확인했다. 읽기 실패 UI는 코드 계약 테스트만 통과했으며 서버 실패를 강제 재현하지 않았다.
브라우저 콘솔내부 클릭 흐름에서 콘솔을 비운 뒤 새 오류는 없었다. 전체 페이지 새로고침에서는 manifest.webmanifest 404와 React Native Web 애니메이션 경고가 보였다. 핸드폰 기능 오류로 단정하지 않고 별도 웹 셸 점검 대상으로 남긴다.
앱/localhost 동등성npm run app:parity는 현재 8081과 공개 QA APK가 같다고 판정. 이 브랜치 수정본은 둘에 반영되지 않은 별도 미리보기다.
남은 제약
  • 개인 비서·지출·뮤지엄 등 일부 항목은 아직 원래 독립 화면의 전체 기능을 핸드폰에 이식하지 않았다. 내부에서는 승인 루틴·저장 기록 등 연결된 실제 자료의 제한된 보기 또는 미연결 상태만 제공한다.
  • 수정본을 실제 QA 앱과 8081에 동시에 반영하려면 이 브랜치의 통합·QA APK 빌드·8081 재기동 및 모바일 재검증이 필요하다.
  • npx expo-doctor는 19/22 항목 통과, 3항목 미통과(프로젝트의 런타임·의존성 점검). 이번 핸드폰 변경과의 인과 관계는 확인하지 않았다.
  • 이번 QA에서 발생한 새 유료 호출·데이터 변경은 없다.
