답변 근거가 연결되는 순서

일반 기록 원문은 자동으로 추가하지 않습니다. 소스만 있는 상태에서 위키 페이지 인용을 만들어내지 않습니다. 모델에 전달하는 자료는 비신뢰 데이터로 감쌉니다.

실제 GUI와 서버에서 확인한 것
  • 기존 8081 GUI의 북극성·위키·기록·대시보드·대화 5개 화면: HTTP 200, 화면 표시, pageerror 0, 425px 가로 넘침 0.
  • 위키·대시보드는 로딩 종료를 기다린 추가 확인까지 통과.
  • QA 서버 조회: Brain 등급, 승인 카드 1개와 제안 2개. 보존된 실제 호출 기록은 인터뷰 2건과 페르소나 생성 1건.
  • 실제 GUI에서 합성 QA 기록 1건을 저장하고 완료 화면을 확인. 추가 모델 호출 0건.

이는 원래 Observatory GUI의 실제 실행 증거입니다. 새 통합 코드 전체의 운영 배포 증거를 뜻하지 않습니다. 새 브라우저의 홈 이동은 온보딩으로 전환되어 홈 재접속 숨김은 별도로 확인하지 못했습니다.

로컬 검증 범위와 한계
  • 통합 전체 검사: 10,324개 통과. 웹 출력 검사: 127개 문서 통과.
  • 원문 저장→수동 승격→프롬프트→인용 열기와 자동 저장 동의: 10개 스위트, 126개 검사.
  • Paddle: 17개 스위트, 507개 검사. GA4·인증: 36개 스위트, 535개 검사. 실제 결제나 분석 전송은 하지 않음.
  • Sandbox CSP: 23개 검사와 실제 Chrome에서 모의 응답을 사용한 연결 허용·차단 확인.
  • 가입 확인과 Polaris 동시성은 실제 로컬 PostgreSQL에서 실행. 운영 DB에는 마이그레이션을 적용하지 않음.
  • 새 가입 계약의 익명 RPC는 고정된 메타데이터만 공개. 변경 감시에서 보조 함수 교체 누락을 발견해 검토 대상으로 추가.
  • 이미 서버가 수락한 쓰기의 소급 취소, 실제 모델 답변의 품질, 실기기 동작은 이 회귀 검사의 보장 범위 밖.
운영 적용 순서와 남은 확인
  1. 콘솔 소유자가 DB 번호를 예약하고 선행 계약과 ACL을 확인. Polaris는 0189/0190 및 계정 삭제 완료 fence가 먼저 필요.
  2. Polaris 비활성 상태에서 DB·승인 RPC를 준비하고 4개 LLM proxy의 공유 가드를 배포. 예약·정산·승인·삭제 경합 확인 뒤 켬.
  3. 가입 email-v4 계약 적용 뒤 공개 상태 RPC와 실제 이메일 확인을 검사. 이전 v2/v3 동의 기록은 보존.
  4. 광고 SSV와 Paddle은 각 문서의 OFF·진행 중 요청 종료·DB·Edge·canary 순서를 따름.
  5. 별도 Paddle sandbox에서 결제·갱신·환불과 운영 원장 무변경을 확인. 실제 서비스 생성·배포·결제는 아직 실행하지 않음.
  6. 일반 사용자 경로의 페르소나 생성, 실제 근거 인용, GA4 수신과 모바일 실기기 확인. 광고 활성화 전에는 AdMob 계약 주체·이전 국가·보유 조건을 운영 증거로 확정.

서비스 동의 v2는 제공자 호출 전 검사를 갖지만, 호출 중 철회를 정산 직전에 다시 검사하는 처리는 남아 있습니다. 해당 계약의 활성화 조건으로 기록했고 일반 자동 저장·분석 설정을 서비스 동의로 대신 해석하지 않았습니다.
