사용자가 할 수 있는 일

개인정보 설정에서 현재 AI 동의 상태를 확인하고, 다섯 필수 항목을 확인한 뒤 동의하거나 AI 처리 동의를 철회할 수 있습니다. 철회는 기록·계정·다른 개인정보 설정을 바꾸지 않습니다.

서버 준비가 안 됐거나 저장 응답이 불확실하면 성공을 표시하지 않습니다. 충돌 뒤에는 현재 상태를 다시 읽고 새로 선택합니다. 대화·북극성에서 동의 오류가 발생하면 이 화면으로 이동하며 이전 요청을 자동으로 다시 보내지 않습니다.

동의를 받는 동안에도 철회 적용

collect는 신뢰 영수증이 전혀 없는 기존 계정의 접근만 잠정 유지합니다. 첫 동의·철회는 기존 요청의 token을 무효화합니다. 기존 선택 동의 거절은 서비스 동의를 다시 저장해도 보존됩니다.

새 설정을 켠 것만으로 모든 서버가 준비됐다고 판단하지 않습니다. 운영에서 기존 요청 종료·네 프록시 배포·제한 canary를 확인해야 합니다.

실제 브라우저 화면

실제 QA 계정 로그인 후 동의 응답만 브라우저 내 fixture로 대체했습니다. 운영 동의 저장의 증거가 아닙니다.

남은 운영 검증

DB 번호 승격·적용, 네 proxy와 관리 Edge 배포, 기존 요청 종료와 canary, 실제 계정의 동의 수집률 확인이 남습니다. enforce 전에는 전체 active 계정의 uncovered/blocked가 0이어야 합니다. 명시 철회 계정은 따로 셉니다.

이미 제공자에게 보낸 입력·발생 비용·완료된 결과는 회수하지 못합니다. 최종 DB 확인과 HTTP 전달 사이의 철회를 원자적으로 묶지는 못합니다. 기존 서버 승인과 Grok 보류를 유지하며 이번에는 운영 변경을 하지 않았습니다.
