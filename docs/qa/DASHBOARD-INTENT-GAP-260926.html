데이터 차이가 아니라 대시보드의 목적을 축소한 것이 핵심 문제

Simon의 원본은 무엇을 먼저 하고, 무엇이 변했고, 어떤 근거를 믿을지 결정하는 운영 화면이다. 현재 앱은 기록 두 건과 루틴 현황을 보여주는 휴대전화 요약에 머물렀다. 사용자의 지적이 맞다.

원본의 중심

최우선 행동 → 한눈 지표 → 일정·추세 → 연결 상태·출처 신뢰도

현재 앱의 중심

요약 2건 → 오늘 루틴 → 인터뷰 원문 → 생활 영역 기록 수

판정

기능의 기본 표시와 이동은 동작하지만, 의도한 ‘개인 운영 대시보드’의 제품 적합성은 미달한다.

어디서 달라졌나

사용자 의도와 원본현재 앱의 대응빠진 의미
맨 위에 ‘지금 가장 먼저 할 일’ 1개와 선정 이유인터뷰·기록 중 가중치가 높은 2개를 나열행동 우선순위와 바로 실행하는 경로가 없음
마감·진행률·미읽음·실패 등 상황별 KPI와 이전 대비 변화생활 영역 기록 수와 오늘 루틴사용자에게 중요한 신호, 증가·감소, 위험도가 보이지 않음
다가오는 일정과 시간축, 반복 문제의 추세승인된 반복 루틴의 7일 전망만 조건부 표시일정·연동 자료 기반의 계획과 패턴 판단이 빠짐
실데이터·프록시·미연결·샘플을 화면에서 구별자료가 없는 영역을 대체로 생략하고, 연결 상태는 설정으로 분리대시보드 안에서 ‘왜 비었는지’와 믿을 수준을 알기 어려움
쉬운 설명/전문가 설명의 점진 공개원문 기록으로 이동하는 카드숫자의 목적·집계법·한계를 화면에서 이해하는 층이 없음

왜 이렇게 만들었나

내가 원본의 Calendar·Gmail·Linear·GitHub 지표를 Simon 개인 계정에만 적용되는 데이터로 보고, QA 계정에서 확인 가능한 기록·루틴만 쓰도록 좁혔다. 없는 수치를 만들지 않겠다는 판단은 맞았지만, 그 과정에서 자료가 없는 카드의 상태를 정직하게 보여주는 대신 카드 구조 자체를 버렸다. 또 ‘휴대전화 안의 앱’과 PIXEL-CLAY 스타일을 우선하면서 화면을 460px 폭의 단일 목록으로 만들었다. 이는 시각 언어를 바꾸는 일이지 원본의 의사결정 흐름을 빼도 된다는 뜻은 아니었다.

갱신 요구도 좁게 구현했다. 현재 기본 1시간은 앱이 열린 동안 이미 저장된 자료를 다시 읽는 주기이지, 연결 서비스의 최신 데이터를 가져와 비교·재구성하는 주기가 아니다. 이전 QA 보고서는 클릭과 표시를 검증했지만 이 요구와의 차이를 합격 기준에 넣지 못했다.

바로잡을 기준

1 · 구조를 보존

휴대전화의 픽셀 스타일은 유지하되, 첫 화면은 ‘지금 할 일 1개 → 핵심 신호 → 시간축·추세’ 순서로 바꾼다. 상세 설명과 출처는 탭으로 펼친다.

2 · 비어 있어도 정직하게

연결 자료가 없으면 숫자를 만들지 않고 ‘미연결/자료 없음/오래됨’을 표시한다. 개인별 카드 선정도 소스 상태와 행동 가치를 함께 반영한다.

3 · JSON을 진짜 계약으로

카드 유형, 입력 출처, 최신성, 우선순위, 다음 행동, 근거 수준, 오류·빈 상태, 갱신 정책을 규칙화한다. 단순 가중치 목록으로 끝내지 않는다.

원본의 특정 수치는 그대로 가져오면 안 된다. 첨부 HTML은 SNAPSHOT=2026-09-20 21:18 KST, NEXT_REFRESH=2026-09-21 07:00 KST가 박힌 자체완결 스냅샷이다. 보존해야 할 것은 오래된 수치가 아니라 행동·지표·추세·근거를 한 화면에서 판단하는 방법론이다.

비교 근거와 검증 범위

원본: 사용자가 첨부한 원본 HTML을 읽고 로컬 Chrome에서 1440×1000 및 425×812로 렌더링했다. 앱: 앞선 QA 계정의 425×812 화면 캡처와 서버 작업트리 src/components/dashboard/DashboardPhone.tsx, src/lib/dashboard/summary.ts, dashboard-rules.json을 대조했다. 이번 진단 때 QA 브라우저 세션은 로그인 화면으로 돌아가 있어 라이브 데이터를 재검증하지 않았다.

원본 역시 HTML 파일 자체가 외부 서비스에 실시간 연결되는 것은 아니다. 파일 상단의 스냅샷 상수를 외부 갱신 작업이 새 자료로 교체하는 방식이다. 원본의 날짜·개인 계정 지표를 현재 QA 계정의 사실로 취급하지 않았다.

이번 작업은 비교·원인 진단만 했다. 앱 코드, 데이터, 설정은 변경하지 않았다.
