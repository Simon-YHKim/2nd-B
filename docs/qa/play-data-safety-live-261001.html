정정 근거와 한계

vc56 첫 실행 네트워크 QA는 가입·로그인·동의 전에 앱 UID가 Firebase Installations와 연결된 사실을 기록했다. Firebase 공식 공개 안내는 설치 ID(FID)가 자동 생성·수집된다고 설명한다. 현행 개인정보처리방침도 Android 첫 실행의 자동 등록과 앱 설정에서 끌 수 없음을 명시한다. Google Play 데이터 보안 안내의 ‘선택’은 수집에 대한 opt-in 또는 opt-out을 포함한다. 따라서 현재 출고 앱의 FID를 ‘필수’로 분류하는 것이 근거에 맞는다.

vc56 QA는 TLS 본문에서 FID 값 자체를 복호화하지 않았다. Play의 ‘기기 또는 기타 ID’ 행에는 FID 외 다른 식별자도 합쳐질 수 있다. Google Play의 분류 안내는 Health Connect의 걸음·운동을 운동 정보에, 파일명도 파일·문서에, Firebase 설치 ID를 기기 ID에 포함한다. 이 판단은 공식 분류·vc56 코드·앱 첫 실행 관찰·현재 방침을 종합한 것이다.

vc56 파일 선택 코드는 PDF·DOCX 본문 추출을 건너뛰고 TXT·MD 등 지원하는 텍스트 형식만 읽는다. 저장 경로는 텍스트가 없을 때 파일명·유형·크기의 대체문을 만들고, 이 문자열을 클리퍼 분류와 저장에 사용한다. 이전 보고서의 ‘PDF·문서 등의 내용’이라는 표현은 PDF·DOCX 본문까지 전송하는 것으로 읽힐 수 있어 여기서 정정한다. 바이너리 파일 자체의 업로드는 이 경로에서 확인되지 않았다.

vc56의 EAS 설정은 클리퍼 분류의 backbone vendor를 OpenAI로 고정하고 자동 장애 전환을 껐다. OpenAI API DPA는 고객 지시에 따른 수탁 처리를 명시하고, Play 안내는 이런 서비스 제공자에게 맡긴 전송을 ‘공유’에서 제외한다. 따라서 확인한 vc56 파일 분류 경로의 OpenAI 전송은 현재 초안의 ‘수집, 공유 아님’과 부합한다는 추론이다. 이 판단은 실제 계정·계약 적용과 다른 활성 버전의 파일 경로까지 확인한 판정이 아니다.

vc56 AAB에는 Google Mobile Ads SDK가 포함돼 있지만 첫 실행 56초의 네트워크 QA는 Firebase Installations·Expo Updates 연결만 확인했다. vc56 소스는 광고 모듈 16.3.0을 고정했고, 설치된 동일 판본은 Android GMA 25.0.0을 선언한다. 현재 Google의 광고 SDK 공개 안내는 최신 25.5.0을 다루므로 vc56 출고 AAB의 실제 전송을 그대로 대변하지 않는다. 그래서 위치·진단·앱 상호작용의 필수/선택과 목적은 원래 신고대로 두고 추가 검증 대상으로 유지한다.

vc56 원본 AAB(SHA-256 a8e5fe7caa7a33f955113ae8207499c5a7919ac31e0b067355691dcc451450bc)의 병합 매니페스트를 bundletool 1.17.2 dump manifest로 재확인했다. MobileAdsInitProvider가 있고 DELAY_APP_MEASUREMENT_INIT=true다. firebase_analytics_collection_enabled=false와 io.sentry.auto-init=false도 있다. vc56의 광고 법률 게이트는 항상 닫혀 있고, 광고 SDK 초기화는 그 게이트를 통과한 광고 흐름에서만 호출된다. 이 정적 설정은 광고 SDK 전체가 시작 전·이후에 데이터를 전혀 전송하지 않는다는 증거가 아니다.

Google 릴리스 기록에는 25.0.0의 별도 데이터 유형 목록이 없고, 현재 공개표는 25.5.0의 IP 주소·앱 상호작용·진단·식별자 자동 수집·공유를 설명한다. DELAY_APP_MEASUREMENT_INIT은 과거 앱 측정 시작을 늦추기 위한 설정이었으며, Google 시작 안내는 SDK 초기화가 광고 사전 로드로 이어질 수 있다고 경고한다. 플래그나 ‘아직 광고 요청 전’이라는 사실만으로 vc56의 모든 광고 데이터 전송이 차단됐다고 해석하지 않는다.

Firebase 공개표는 Installations의 자동 수집을 설치 ID와 Firebase user agent로 명시한다. Expo Updates 프로토콜은 업데이트 서버가 요청의 출발 IP를 사용할 수 있다고만 한다. 앞선 첫 실행 캡처의 두 목적지만으로 위치 추론·진단 보관·앱 상호작용 수집 여부를 확정할 수 없다. 현재 Play 양식의 세 항목을 축소하거나 최종 제출하려면 vc56의 실제 광고 SDK 동작과 수신자별 데이터 사용, 배포 중인 버전 전체를 추가로 확인해야 한다.
