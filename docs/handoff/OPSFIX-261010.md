## 구현과 서버 변경 불필요 근거

### G5-05

`useChatPlans`는 제안별 첫 확인에서 기존 `expo-crypto`의 UUID를 만든다. 동기 in-flight
잠금은 그대로이며, 응답 실패나 편집기 닫기로 UUID를 버리지 않는다. 소유자 또는 대화가
바뀌면 제안별 ID를 비운다. 서로 다른 제안은 내용이 같아도 별개의 루틴을 만들 수 있다.

`saveChatPlan`은 이 ID와 기존 owner lease의 AbortSignal을 저장 함수에 전달한다.
`createRoutineFromRecommendation`의 새 경로는 현재 소유자를 확인하고
`upsert({ id, ...reviewedFields }, { onConflict: "id" })`를 사용한다. ID가 없는 기존
호출부는 원래 INSERT를 유지한다. 예약 알림의 식별자도 기존 `routineReminderId(owner, id)`라
같은 루틴 재시도에서 같은 식별자를 사용한다.

`db/migrations/0048_ops_routines.sql`에 이미 `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`와
authenticated의 owner-only `FOR ALL USING/WITH CHECK (user_id = auth.uid())`가 있다.
클라이언트 ID의 INSERT와 같은 소유자의 UPDATE가 허용되므로 새 unique 열·RPC·migration이
필요하지 않다. 이는 저장소 SQL의 확인이며 운영 DB를 조회하거나 호출한 결과는 아니다.

보장 단위는 **동일한 대화 제안의 재확인**이다. 채팅 자체가 메모리 전용이며
(`src/app/secondb.tsx`), 앱 재시작 뒤 옛 대화 제안을 복원하는 경로는 없다. 재시작 후 사용자가
새 대화에서 같은 내용을 다시 요청하는 것은 새 제안이다. 내용 전체의 영구 중복 제거,
이미 만들어진 중복 행의 정리, 별도 `/ops` 추천 저장 경로는 이번 감사 호출부 수정에 포함하지 않는다.

### G5-06

기존 owner별 큐·암호화 저장소·삭제 fence를 유지한다. 순서는 기록 읽기 → strict 예약 취소
시도(기존 최대 5초) → 소유자/fence 재확인 → 해당 기록만 저장소에서 제거 → 결과 반환이다.
취소 실패만 잡으며 저장소 실패는 계속 예외로 전달한다. 따라서 저장소 실패에는 기존
`deleteFailed`가 표시되고 기록은 재시도할 수 있다. 계정 전환 때는 늦은 삭제나 안내를 발행하지 않는다.

성공은 `true`, 쓰기 불가는 `false`, 기록은 지웠지만 예약 취소를 확인하지 못한 경우는
`"alarm-uncertain"`다. 목록은 세 번째 결과에서 기록을 제거하고 기존 `alarmFailed` 문구를
표시한다. **OS 예약이 남아 나중에 울릴 가능성은 남는다.** 새 문구나 취소 성공 주장은 추가하지 않았다.
삭제한 ID의 알림을 나중에 눌러도 기존 응답 처리기는 저장 목록에 없는 ID로 상세를 열지 않는다.

웹은 기존 설계상 기기 암호화 리마인더를 생성·조회하지 않고 ICS만 내보낸다. 브라우저가
네이티브 기록에 접근하도록 바꾸지 않았다. 웹에서 이미 내보낸 외부 캘린더 항목을 지우는 기능도 아니다.

### G5-07

그룹을 별도 state로 두지 않고 `OPS_DOMAIN_GROUP[draft.domainId]`에서 계산한다.
다른 그룹을 선택하면 해당 그룹의 첫 분류를 draft에 넣고, 현재 그룹을 다시 누르면 기존 선택을 유지한다.
편집 중 busy 검사도 기존 `update` 경로를
통하므로 표시 그룹과 저장 분류가 따로 바뀔 수 없다. 화면 배치·문구·i18n 키는 그대로다.

## 검증 방식

RN 렌더러 대신 기존 TypeScript 소스 실행 harness와 순수 저장 함수 테스트를 사용했다.
서버 모형은 행을 실제 Map에 반영한 뒤 응답만 실패시켜, 재확인 뒤 행 수가 1인지 검사한다.
네이티브 테스트는 실제 취소 함수에 실패·미지원·시간초과를 주입한다. 실제 OS 실행은 아니다.
각 변경 규칙의 변이를 한 번씩 적용하고 테스트 실패 확인 후 파일 원복·재통과를 확인한다.
