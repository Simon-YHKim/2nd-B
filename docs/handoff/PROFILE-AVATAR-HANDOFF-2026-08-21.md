2nd-Brain 저장소에서 **프로필 캐릭터 · 아바타 시스템**을 작업한다.
착수 전에 이 보고서를 먼저 열어라. 실측 근거와 인터랙티브 증거가 전부 여기 있다:

**https://claude.ai/code/artifact/e8f3d955-2212-4c5e-830d-9b3abec4e65d**

## 1. 이게 무슨 기능인가

사용자가 **자기 픽셀 캐릭터를 만들고, 거기에 직업 복장을 입히는** 기능이다.
64×64 픽셀 아바타 · 정수 rect only · 곡선 0 · 안티에일리어싱 0 (PIXEL-CLAY v4 규칙).

캐릭터는 앱 곳곳에서 그 사람을 가리키는 얼굴이 된다 — 프로필 화면, 페르소나 덱,
채팅, 커뮤니티, 공유 카드.

## 2. 지금 상태 (실측, 추측 아님)

## 3. Simon 이 원하는 구조

> "프로필에서 설정한 개인 프로필 캐릭터 특징을 아바타 설정 화면에서 그대로 띄우고,
> 직업별 특징적인 복장이나 악세사리를 붙이는 형태"

**한 캐릭터, 두 레이어.** 나란한 두 설정이 아니라 아래위로 쌓인 두 레이어다.

```
레이어 1 — 나 (프로필에서 만든다)
  type · hair · expr · face · acc · skin · hairColor · cloth
        ↓  아래 레이어가 먼저 그려지고
레이어 2 — 역할 (직업 하나가 셋을 결정한다)
  J.hat 모자(44중 31) · J.cloth 유니폼 색(44중 44) · J.extra 소품
        →  위 레이어는 "겹치는 자리만" 덮는다
```

## 4. 고쳐야 할 것 — 결함 3건

**D1 · 액세서리가 이유 없이 사라진다** — `px-avatar64.js:491`
모자 직업이면 `acc` 19종을 전부 버린다. 귀걸이·목도리·나비넥타이·마스크는 모자와
자리가 겹치지 않는데도 사라진다. 모자 직업 31 × 안 겹치는 소품 4 = **124 조합**.

**D2 · 옷 색이 대체되고 되돌릴 손잡이가 없다** — `px-avatar64.js:477`
`var cloth = J ? J.cloth : sp.cloth;` — 사용자가 고른 색이 계산에서 통째로 빠진다.
스튜디오 색 탭이 안내는 하지만("직업을 고르면 모자와 의상은 그 직업의 고정 색을
써요") 선택지가 없다. 유니폼이 기본값인 건 맞다. 강제일 이유가 없을 뿐이다.

**D3 · 직업을 두 곳에서 따로 묻는다** ← **화면보다 이게 먼저다**
- 앱: `profile_details.occupation` — 자유 텍스트 40자. 비서가 제안을 현실적으로
  만들려고 쓴다 (`src/lib/persona/profile-details.ts`)
- 프로토타입: `avatar.job` — 44종 열거형. 그림을 그리려고 쓴다

둘은 서로를 모른다. 사용자가 같은 사실을 두 번 적는다. **Simon 이 말한 "탭이 갈라져
있다"의 데이터 쪽 얼굴이 이것이다.**

### 결함이 아닌 것 — 건드리지 마라

- **헤어가 잘리는 것(`:482`, `y > 15`)은 정상이다.** 모자 밑 정수리만 지우고
  옆머리·뒷머리·포니테일은 남긴다. 실제로 모자를 쓰면 그렇게 보인다.
- **얼굴 디테일(안경·수염·주근깨)은 현행에서도 이미 유지된다.**
- **`sb-persona.jsx:283 personaAvatar()` 는 이미 맞다.** "얼굴은 내 프로필 그대로,
  직업만 바뀐다"를 구현해 뒀다. 다만 그 주석의 "액세서리는 유지"는 **거짓이다** —
  엔진이 유지하지 않는다. D1 을 고치면 주석이 참이 된다.

## 5. 합성 규칙 수정 (검증됨)

엔진 두 줄 + 표 하나다. 보고서의 "제안 결과" 열은 정확히 이 패치를 적용한 엔진을
Node 로 돌려 뽑은 실제 렌더다. 귀걸이가 사각형 4개만큼 되살아나는 것을 확인했다.

```js
// 머리 위에 쓰는 소품만 모자에 자리를 내준다 (15종)
var HEADTOP = { headband:1, beanie:1, capback:1, flowerpin:1, headphone:1,
                bandana:1, hairclip:1, halo:1, catears:1, crownsm:1,
                hoodup:1, antenna:1, horns:1, visor:1, freckleset:1 };

// :477
- var cloth = J ? J.cloth : sp.cloth;
+ var cloth = (J && sp.wearUniform !== false) ? J.cloth : sp.cloth;

// :491
- if (A3 && sp.acc !== 'none' && !(J && J.hat)) o = o.concat(A3.f(P));
+ if (A3 && sp.acc !== 'none' && !(J && J.hat && HEADTOP[sp.acc])) o = o.concat(A3.f(P));
```

## 6. UI

**두 화면, 한 방향.** 프로필이 캐릭터를 만들고, 아바타가 그 캐릭터를 이미 만들어진
채로 받아 직업을 입힌다. 아바타 화면은 얼굴을 다시 묻지 않는다.

- **프로필 화면** — 탭 2개(모양 · 색). 종류/헤어/표정/얼굴/소품/색.
  **직업 탭이 여기 없다.** 여기는 나를 만드는 자리다.
- **아바타 화면** — 상단에 내 캐릭터가 이미 떠 있다. 분야 12개로 좁힌 직업 격자
  (바둑판, 각 칸에 내 얼굴 + 직업 옷 미리보기 + 이름). 옷 색은 유니폼/내 색 토글.

화면이 지켜야 할 규칙 넷:
1. **미리보기는 항상 최종 합성 결과다.** 탭마다 다른 그림을 보여주면 안 된다
2. **덮은 것은 덮었다고 말한다.** ("모자가 헤드폰 자리를 가져갔어요")
3. **직업은 한 번만 묻는다.** 프로필의 직업 값이 정본
4. **되돌리기가 항상 있다.** 직업 없음으로 가면 원래 캐릭터가 손상 없이 복원

## 7. 작업 순서 — 이 순서에 이유가 있다

1. **합성 규칙을 프로토타입 안에서 먼저 고친다.** `design/pixel_clay_v4/app/2nd-Brain.html`
   을 브라우저로 열어 스튜디오에서 눈으로 확인. 앱은 아직 건드리지 않는다.
   번들은 "받은 그대로" 두는 자료이므로 고친 내용은 `REPO-NOTES.md` 에 적는다.
   *(먼저 고치는 이유: 옮긴 뒤에 고치면 이식과 수정이 한 커밋에 섞여서, 무엇이
   원본 동작이고 무엇이 우리 결정인지 나중에 구별할 수 없다.)*
2. **엔진을 RN 으로 옮긴다.** `ops()` 가 정수 rect 배열을 뱉는 순수 함수라
   `react-native-svg` 의 `Rect` 로 그대로 그린다. `avatarSVG()`(HTML 문자열)는 쓰지 마라.
3. **저장 자리를 만든다.** `users.avatar` jsonb. `resolveProfileDetails` 와 같은
   방식의 좁히기 함수를 **반드시 같이** 만든다 (jsonb 는 클라가 뭐든 넣는 컬럼).
   이때 **본인 외 읽기**를 한 번 생각하고 넘어간다 (§9 참조).
4. **직업을 한 값으로 잇는다** (D3). 방식은 §9 에서 확정됐다 — `occupation` 이 정본,
   `job` 은 그림 열쇠, 44종 밖이면 텍스트만 남는다.
5. **화면 둘을 붙인다.** 프로필에서 캐릭터를, 아바타에서 직업을.
   **여기까지가 이번 범위다** — 다른 화면에 아바타를 띄우는 것은 §9 미결이다.

## 8. 함정

- **밝기 정직성을 깨지 마라.** `src/lib/persona/profile-star.ts` 가 일곱 번째 별의
  밝기를 계산하는데, 세는 것은 **사용자가 자기에 대해 적어 넣은 사실**이다.
  헤어스타일을 고르는 것은 사실이 아니라 취향이다. **아바타를 꾸몄다고 별이
  밝아지면 안 된다.** 그 별이 뮤지엄을 밀어내고 들어온 이유가 정확히 그 반대였다
  (뮤지엄은 L4 고정이라 영원히 밝았고 아무 뜻이 없었다).
  단, `occupation` 은 이미 세는 값이다. 아바타에서 직업을 골라 `occupation` 이
  채워지면 **그건 밝아지는 게 맞다** — 사실이 하나 늘었으니까. 이 구분을 잃지 마라.
- **동물 아바타는 직업을 못 입는다.** 엔진의 동물 분기가 `job` 을 읽기 전에
  `return` 한다 (여우+경찰 = 바이트 단위로 동일한 SVG, 확인함). 동물 몸통용 유니폼
  44종을 다시 그려야 하는 별도 작업이다. **이번 범위 밖.**
- **PIXEL-CLAY 이주 전체와 순서를 다투지 마라.** 아바타는 지금 앱에 없으므로 어느
  시각 체계로 옮겨도 되돌릴 것이 없다. 다만 화면 껍데기는 그 화면의 이주 상태를
  따른다 — 아직 안 옮긴 화면이면 현행 M3-deepspace 규칙으로 그린다.
- **`REPO-NOTES.md` 의 폰트 서술은 낡았다.** "Galmuri 나머지 3종이 남았다"고 적혀
  있지만 `src/theme/typography.ts` 를 보면 **2026-08-20 에 5종 전부 등록됐다.**
  그 문장을 근거로 폰트 작업을 다시 발주하지 마라.
- **조사 처리를 원본에서 베끼지 마라.** `sb-persona.jsx:324` 의 `hasJong` 은
  (으)로 의 ㄹ 예외가 없다. 옮길 때 ㄹ 예외를 넣고 5쌍 전부 지원하고 테스트를 붙여라.
- 저장소 규칙: `npm run verify` 통과 · `src/lib/theme/tokens.ts` 의 `semantic.*`
  경유(hex 리터럴 금지) · 워크트리는 `.worktrees/` 안 · main 직접 push 금지.

## 9. Simon 결정 (2026-08-21) — 확정 2건, 네 몫 1건

**확정 · 옷 색 기본값** — 유니폼이 기본값이고 "내 색 유지"가 선택지다. 직업을 골랐으면
그 옷을 입는 것이 자연스러운 기대이고, 되돌릴 손잡이만 있으면 된다. 강제였던 것이
기본값이 된다. 다시 묻지 마라.

**확정 · 직업 열거형** — 44종을 그대로 쓰고 `occupation` 자유 텍스트와 잇는다.
`occupation` 이 사람이 적는 정본, `job` 44종은 거기서 고른 그림 열쇠다. 44종에 없는
직업을 적었으면 텍스트는 그대로 유지되고 그림만 없다. **목록에 맞춰 자기 직업을
고쳐 적게 만들지 마라.**

**네가 정할 것 · 노출 범위** — 아바타를 어디까지 띄울 것인가
(페르소나 덱 · 채팅 · 커뮤니티 · 공유 카드). Simon: "다른 세션에서 결정하도록 두자.
근데 아마 그 내용대로 적용하게 될 거 같아."

그 신호는 그 자체로 설계 지시다. **이음매는 넷을 다 감당하게 넓게, 화면 배선만 좁게.**

- 넓게: `users.avatar` 를 만들 때 **본인 외 읽기**를 처음부터 생각하고 넘어가라.
  커뮤니티와 공유 카드는 남이 내 아바타를 보는 자리다. 나중에 RLS 를 다시 여는
  것보다 지금 묻는 편이 싸다. 엔진 쪽은 이미 준비돼 있다 — `ops()` 는 크기에
  무관하고 `crop`(머리 영역 12–52 × 0–40)이 40px 이하 칩까지 커버한다.
- 좁게: **네 표면에 실제로 붙이는 일은 이번 범위가 아니다.** 각 표면이 자기
  동의·가시성 규칙을 갖는다(커뮤니티는 이미 성인 한정, 공유 카드는 밖으로 나가는
  이미지). 결정된 다음의 일이다.
