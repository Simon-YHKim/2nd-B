# 채팅 입력·표정·문맥 판정 수정

2026-10-09 · `fix/chat-reliability-261009`

## 범위와 완료 기준

- 자동 줄바꿈·한글 조합·입력 삭제 중 같은 입력 요소와 커서를 유지한다.
- 메시지 아바타는 해당 답변의 표현을 따른다. 과거 질문의 감정으로 새 답변을 덮지 않는다.
- 명확한 의도 부인과 일상적인 업무 완료 표현을 구분한다. 미확인 문맥이나 실제 위험 행동이 함께 있으면 기존 보호를 유지한다.
- 앱과 Edge에서 같은 문맥 판별 코드를 사용한다. 원문·모델 입력·기존 단어 목록·출력 검사·감사 기록은 보존한다.
- 회귀 검사, 전체 verify, CI, 8081 반영과 브라우저 확인을 거친다. 서버 코드는 실제 배포 전까지 미적용으로 구분한다.

## 구현과 검증 방법

### 입력창

웹에서 실제 입력창을 일시적으로 높이 0으로 만든 뒤 측정하던 방식을 별도 숨겨진 측정 요소로 옮긴다. 입력 중인 요소의 선택 영역, 조합 상태와 스크롤을 측정 때문에 건드리지 않는다. 네이티브의 content-size 경로는 유지한다.

초기 검증은 빈 대화에서 320·390·460·768px 자동 줄바꿈, 한글 조합, Shift+Enter, 최대 높이 전환을 확인했다. 이 조건에서는 포커스 이탈이 재현되지 않았다. 측정 중 실제 입력창을 축소하지 않는 동작을 별도 회귀 검사로 고정했다.

PR #2190 이후 8081에서 여러 메시지를 넣은 대화로 재검증하자 포커스 이탈을 재현했다. 입력창이 높아지면 대화 영역의 onLayout이 scrollToEnd를 호출하고, React Native Web의 ScrollView는 `keyboardDismissMode="on-drag"`이면 프로그램이 일으킨 scroll 이벤트에서도 dismissKeyboard를 호출했다. 실제 호출 스택에서 `_handleScroll → blurTextInput → HTMLElement.blur`를 확인했다. 웹에서는 `none`을 사용하고 iOS의 interactive, Android의 on-drag는 유지한다. 측정 방식 변경만으로 해결됐다고 보고하지 않는다.

### 답변 표정

`presentation-policy.ts`에서 현재 답변의 사과, 공감, 축하, 감사, 설명·계획, 인사 표현을 판별한다. 코드·인용문은 제외하며 불명확한 답변과 보호·오류 응답은 중립으로 남긴다. 새 모델 요청은 추가하지 않는다. 규칙으로 잡지 못하는 자연어 표현은 있을 수 있다.

### 문맥 판정

`src/lib/safety/crisis-context.ts`는 외부 의존성이 없는 검사 전용 변환이다. 클라이언트와 Edge가 같은 함수를 import한다. 명확한 전체 문장 틀에만 예외를 적용하고, 다른 위험 표현이나 미확인 후속 문장을 지우지 않는다. 검사 사본은 모델이나 저장 계층에 보내지 않는다.

회귀에는 수면 부족 원문, 명확한 부인, 업무 완료 문구, 질문형·이중 부정·현재 행동·혼합 언어·정규화·복수 출현을 포함한다. 원래 위험 코퍼스의 정답과 통과 기준은 바꾸지 않는다. 실제 proxy 소스를 실행하는 테스트와 LLM 경계 테스트로 입력 차단·출력 교체·원문 보존을 함께 확인한다.

## 적용 및 운영 경계

앱 코드는 PR → CI → main → 8081 순서로 반영한다. 공유 검사 함수를 소비하는 Edge 함수도 배포해야 서버에서 같은 판정을 한다. 기존 API·DB 스키마·기능 플래그·인증 정책 변경은 없다. 배포 승인과 실제 적용 결과는 완료 보고에서 구분한다.

고정 보호 응답이 이미 저장된 과거 대화는 이 수정으로 재작성하지 않는다. 제공된 첫 수면 문장이 어떤 생성 답변에서 보호 응답으로 바뀌었는지는 원래 생성 원문 없이 확정할 수 없다.
