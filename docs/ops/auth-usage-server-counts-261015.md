# T13 · 기존 서버 로그로 가입·로그인 수 확인

Q-261014-08은 서버 기록 집계를 먼저 하고, 성인이 동의한 앱 통계 수집은 법무 문구가 준비된 뒤 진행한다. 이 문서는 **이미 존재하는 Auth 감사 로그의 읽기 전용 집계**다. Firebase/충돌 수집·앱 시작 이벤트·새 동의·IP/기기 정보 수집을 켜지 않는다.

## 읽는 곳과 뜻

`auth.audit_log_entries` SQL 표가 비어 있어도 로그가 없다고 단정하지 않는다. 이 프로젝트는 Supabase unified logs의 `auth_audit_logs`에 Auth 이벤트를 제공한다. 2026-10-15 확인에서는 Postgres 감사 표와 unified logs의 결과가 달랐다. 실제 관측 수치는 사용자 보고서에서 QA와 나누며 공개 저장소에 계정·이메일·IP·원본 로그를 복사하지 않는다.

- `recorded_login_events`: 보존된 감사 로그의 `login` 이벤트를 `audit_log_id`로 중복 제거한 수. 로그인 횟수이며 사람 수나 기기 수가 아니다. 토큰 갱신·폐기는 로그인으로 세지 않는다.
- `actors_with_recorded_login`: 그 로그에 등장한 서로 다른 actor 수. 활성 사용자 수나 제품의 실사용자 수로 이름을 바꾸지 않는다.
- `recorded_signup_events`: 보존된 `user_signedup` 이벤트 수. 가입 화면 방문·가입 시도·이메일 확인 완료·현재 계정 수와 구분한다. 제공자/확인 방식별 의미가 같은지는 별도 확인한다.
- `known_qa`: 저장소 `.env.test`의 지정 QA 계정. `other_account`는 그 계정이 아니라는 뜻일 뿐, 직원·다른 테스트 계정이 모두 제거됐다는 뜻이 아니다. actor가 없으면 `unknown_actor`다.
- 감사 ID가 없는 줄은 이벤트 수에서 빼고 `rows_missing_audit_id`로 드러낸다. 누락이 있으면 전체 활동 수라고 보고하지 않는다. 계정 수와 이벤트 수를 더하지 않는다.

## 재현 순서

1. 읽을 구간을 ISO8601 시작·끝으로 고정한다. KST 하루는 전날15:00Z부터 당일15:00Z까지다. 오늘은 관측 시각까지의 **진행 중인 하루**다. `query_logs`에 `iso_timestamp_start`와 `iso_timestamp_end`를 명시하며 한 요청은24시간 이하다. 기본 최근24시간에 맡기지 않는다.
2. `SELECT source, count() AS retained_events FROM logs GROUP BY source ORDER BY source`로 그 구간의 로그 가용성을 확인한다. 필요하면 `auth_audit_logs`의 `mapKeys(log_attributes)`만 읽어 필드 이름을 확인한다. 원본 payload/이메일/IP/사용자 에이전트를 출력하지 않는다.
3. [집계 SQL](auth-usage-server-counts.sql)의 `__QA_TEST_USER_ID__`를 `.env.test`의 `QA_TEST_USER_ID`로 바꾼다. UUID 형식인지 먼저 검증하고, 치환하지 않은 템플릿은 실행하지 않는다. 값은 공개 QA 식별자이며 결과에는 출력하지 않는다. service_role 키는 필요하지 않고 채팅에 보내지 않는다.
4. 같은 시작·끝을 `query_logs`에 넘겨 ClickHouse SQL을 실행한다. 이 파일은 Postgres SQL이나 DB migration이 아니므로 `execute_sql`/`apply_migration`에 넣지 않는다. 쿼리는 집계 SELECT만 수행하고 테이블·설정·기능 플래그를 만들거나 바꾸지 않는다.
5. 결과는 관측 시각·시간대·구간·로그 가용성·QA 제외 범위와 함께 기록한다. 한 구간이 실패/미지원/만료되면 그 구간은 미확인이다. 오류를0으로 바꾸지 않는다. 결과 행이 없으면 “보존된 이벤트 없음”이며 실제 활동0이라고 단정하지 않는다.

여러 날을 비교하려면 최대24시간씩 겹치지 않는 구간으로 나눈다. 경계의 이벤트가 중복될 수 있는 제공 방식이면 감사ID를 기준으로 같은 이벤트가 두 번 세어지지 않는지 별도로 확인한다. 보존 기간 밖 과거를 `users.last_sign_in_at`으로 채우지 않는다. 이 값은 마지막 로그인 하나만 보존하므로 로그인 횟수를 복구하지 못한다. `auth.users.created_at` 역시 삭제된 계정·미확인 가입·이관 계정을 포함하거나 제외하는 다른 지표다.

## 아직 남은 T13

이 집계는 앱 통계 기능 전체 완료가 아니다. 자동 집계 스케줄·보존 기간 밖 누적·관리 화면은 구현하지 않았다. 새로운 진단/사용 통계를 수집하는 쪽은 10-17 법무 문구·성인 별도 동의·미성년 잠금과 서버 계약을 먼저 확인한다. 충돌 수집·지문 잠금·녹음/사진 공유·오프라인 띠는 사용자 결정대로 같은 새 APK 묶음에서 기기 검증한다. 기존 비활성화 검사를 이 문서 때문에 완화하지 않는다.

검증: 최종 SQL 템플릿을 지정 QA UUID로 치환해 `2026-10-14T15:00:00Z`~`2026-10-15T14:27:34Z`의 같은 고정 구간에서 실제 read-only `query_logs`로 실행했다. QA/다른 계정 구분, 감사ID 중복 제거, 가입 이벤트0 표시, 토큰 갱신·폐기의 별도 집계를 확인했다. 결과의 계정별 원문·식별자는 출력하지 않았다. 로그의 장기 완전성이나 자동 집계를 검증한 것은 아니다.
