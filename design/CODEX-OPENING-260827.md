# 코덱스 인계 — 오프닝 파인튜닝 (2026-08-27)

발주: *"에셋의 일관성 있는 적용은 마음에 들지만, 에셋의 움직임이 이상하다."*

이 문서는 그 진단을 실측으로 확정하고, 고치는 순서를 계약으로 적는다.

---

## 0. 결론부터 — 움직임이 이상한 게 아니라 **움직임이 없다**

실측이다. 두 오프닝의 에셋을 나란히 재면:

| | 원래 것 (코덱스 제작) | 지금 것 (앱에 들어가 있는 것) |
|---|---|---|
| 에셋 | `design/hustlek-opening-v1/hustlek-opening-atlas.png` | `assets/deepspace/secondb-head-front.png` |
| 크기 | **640×776** (아틀라스) | **1254×1254** (한 장) |
| 담긴 프레임 | 보행 12셀 + 회전·접안 키포즈 6셀 + 망원경 1셀 + 배경 1장 | **1장** |
| 재생 | 165프레임 × 80ms = **13.2초** | 프레임 없음 |
| 캐릭터 동작 | 걸어 들어옴 → 감속 → 측면·대각·후면 회전 → 팔 올림 → 접안 → 카메라가 하늘로 팬 → 북극성 반짝임 | **없음** |
| 실제 움직임 | 위 전부 | `opacity 1→0` (2,500ms) → `opacity→1` + `scale→1.05` + 심장박동 루프(1,400ms) → 탭하면 `scale→4` (800ms) |

**즉 지금 오프닝은 캐릭터를 애니메이션하지 않는다.** 정지 초상화 한 장의 투명도와
크기를 트윈하고 있을 뿐이다. 그래서 "이상하다"고 느껴지는 것이 맞다 — 원래 걸어오던
캐릭터가 지금은 제자리에서 커졌다 작아졌다 한다.

**클로드 디자인이 잘못한 게 아니다.** 일관성 있는 **정면 초상 한 장**을 만들어달라는
요구를 정확히 수행했다. 그 결과 앱 전체에서 같은 얼굴을 쓰게 됐고(발주자가 마음에
들어한 부분), 대신 **스프라이트 시트가 사라졌다.**

정본 코드: `src/components/ui/LoadingScreen.tsx` (431줄).
상수: `MIN_INTRO_MS 2500` · `PER_MESSAGE_MS 1500` · `ENTER_READY_MS 400` ·
`PULSE_PERIOD_MS 1400` · `ZOOM_MS 800` · `AUTO_CONTINUE_MS 4000` · `HARD_READY_MS 9000`.

## 1. ⚠ 착수 전 Simon 결정 1건 — 누가 주인공인가

이 둘은 **다른 캐릭터**다. 코덱스가 추측하면 안 된다.

| | 허슬케이 (HustleK) | 세컨비 머리 (SecondB head) |
|---|---|---|
| 형태 | 전신 치비 — 큰 머리·작은 몸 | **떠 있는 머리** (몸 없음) |
| 특징 | 검은 뿔테 안경, 흰 반팔 티, 카키 긴바지, 황갈색 워크부츠 | 각진 보석 같은 면, 상단 통풍구, 둥근 바이저, 파란 눈, 디스크 귀 |
| 어디 | `hustlek-opening-atlas.png` | `assets/deepspace/secondb-head-front.png`, 앱 전역 |
| 걸을 수 있나 | 그렇다(보행 12셀) | **다리가 없다** |

세컨비 → 허슬케이 **개명은 아직 안 했다**(CLAUDE.md: 구조가 자리 잡은 뒤로 미뤘고
앱 이름과 한 체계로 함께 정한다). 그래서 지금 저장소에는 두 이름이 다 있다.

**✅ [SIMON 결정 2026-08-27] — (a) 허슬케이 전신으로 간다.**

원래 165프레임 연출이 그대로 산다. ⚠ 지금 `secondb-head-front.png` 는 **머리만** 있어
이 결정은 **몸을 새로 그리는 작업을 포함한다.** 스타일 잠금은 §5 가 정본이고
아틀라스 승인 픽셀이 그 위다. 앱 안의 얼굴은 **건드리지 않는다**(오프닝만 전신).

아래는 결정 당시의 선택지 원문이다. 역사 기록이지 열려 있는 질문이 아니다.

- **(a) 허슬케이 전신으로 돌아간다** — 원래 165프레임 연출(걸어와서 망원경을 본다)이
  그대로 산다. 클로드 디자인 스타일로 전신을 다시 그려야 한다. 작업량 최대, 연출 최상.
- **(b) 세컨비 머리로 간다** — 지금 에셋을 살린다. 걷지 못하므로 연출을 바꿔야 한다
  (떠서 다가옴 · 좌우 기울임 · 바이저 점등 · 눈 깜빡임 · 카메라 팬). **추천** —
  발주자가 마음에 들어한 "일관성"이 이 얼굴이고, 앱 전역이 이미 이 얼굴이다.
- **(c) 둘 다** — 오프닝은 허슬케이 전신, 앱 안은 세컨비 머리. 두 캐릭터를 설명해야
  하는 부담이 생긴다. 권하지 않는다.

**결정 전에는 3단계(재적용)에 착수하지 말 것.** 1·2단계는 결정과 무관하게 진행 가능하다.

## 2. 원래 것이 무엇이었는지 — 코덱스가 먼저 확인할 자료

전부 `main` 에 있다. 다른 PC 에서 clone 하면 그대로 따라온다.

| 파일 | 무엇 |
|---|---|
| `docs/HUSTLEK-OPENING.md` (306줄) | **제작 정본.** 좌표·타임라인·금지 규칙·검증 게이트 |
| `design/hustlek-opening-v1/hustlek-opening-atlas.png` | 승인된 픽셀. 640×776 |
| `design/hustlek-opening-v1/hustlek-opening-preview.gif` | 128색 육안 검토본 (7.5MB) |
| `scripts/build-hustlek-opening.py` (606줄) | 결정적 합성기. 165프레임 APNG 를 만든다 |
| `docs/ASSETS.md` §`design/hustlek-opening-v1/` | 프로비넌스 |

**재생성 방법** (네트워크 불필요, Pillow 만 있으면 된다):

```powershell
uv run --with Pillow==12.2.0 scripts/build-hustlek-opening.py
# 또는
python -m pip install Pillow==12.2.0
python scripts/build-hustlek-opening.py
```

성공 조건은 종료코드 `0` 과 `validation.json` 의 `status: "PASS"`.
산출물은 gitignore 된 `Output/hustlek-opening/`.

**아틀라스 셀 배치** (`HUSTLEK-OPENING.md` §4):

```
(0,   0, 640, 360)  승인 배경          1장 640×360
(0, 360, 576, 456)  보행 01–06         6셀 각 96×96
(0, 456, 576, 552)  보행 07–12         6셀 각 96×96
(0, 552, 576, 648)  회전·접안 키포즈    6셀 각 96×96
(0, 648, 128, 776)  북향 망원경        1셀 128×128
```

키포즈 순서: 정측면 정지 → 대각 후면 → 후면 정지 → 후면 팔 절반 → 접안 직전 → 접안 완료.

**원래 타임라인** (§7) — 움직임의 뼈대다:

| 구간 | 시간 | 내용 |
|---|---:|---|
| 0 | 0–800ms | 검은 화면에서 fade in |
| 1 | 800–2,200ms | 초원과 고정 망원경 |
| 2 | 2,200–4,800ms | 보행 진입과 감속 |
| 3 | 4,800–7,200ms | 최종 접근, 회전과 접안 준비 |
| 4 | 7,200–9,000ms | 망원경 관측 hold |
| 5 | 9,000–11,600ms | 카메라가 하늘로 이동해 북극성에 초점 |
| 6 | 11,600–12,300ms | 북극성 한 번 반짝임 |
| 7 | 12,300–13,200ms | 검은 화면으로 fade out |

**⚠ 13.2초는 앱 오프닝으로 너무 길다.** 지금 앱은 최소 2.5초, 자동 진행 4초다.
이 문서가 옮기라는 것은 **길이가 아니라 움직임의 뼈대**다 — 등장 → 정착 → 시선을
하늘로 → 북극성. 압축은 3단계에서 정한다.

**⚠ 저장소에 없는 것 하나.** 이식용 zip
`design/hustlek-opening-v1/hustlek-opening-portable-v1.zip` (7.8MB) 은
`codex/hustlek-imagegen-pilot` 브랜치에만 있고 **main 에는 없다.**
위 표의 아틀라스·스크립트·문서만으로 재생성이 되므로 **없어도 된다.** 필요하면
`git show codex/hustlek-imagegen-pilot:design/hustlek-opening-v1/hustlek-opening-portable-v1.zip > out.zip`.

## 3. 절대 하면 안 되는 것 (원본 문서의 금지 규칙)

- 새 이미지를 **prompt 만으로 재생성**해 승인된 캐릭터를 대체하기
- 다른 게임·제3자 sprite 를 추출하거나 덧그리기
- 프레임별 독립 확대·축소
- bilinear / bicubic / LANCZOS / 안티앨리어싱 / 블러
- 캐릭터에 그라데이션이나 디더링 추가
- 프레임마다 머리·안경·몸통·바지·부츠의 **부피를 바꾸기**
- Pixy skill, Pixy CLI, `.pix`, `pixy.spec.json` 사용
- **승인 없이 atlas 해시나 타임라인 계약 변경**

수정이 필요하면 **해당 셀만 정수 좌표에서 직접** 고친다. 새 생성 결과로 아틀라스
전체를 교체하지 않는다.

여기에 PIXEL-CLAY 규칙이 더해진다: 라운드 0 · 그림자·블러 없음 · 정수 좌표 ·
`steps()` 이징 · 정적 반투명 대신 디더.

## 4. 작업 순서

### 1단계 — 원본 확인 (결정 없이 가능)

1. `docs/HUSTLEK-OPENING.md` 를 끝까지 읽는다.
2. `scripts/build-hustlek-opening.py` 를 실행해 165프레임을 재생성하고
   `validation.json` 이 PASS 인지 본다.
3. 결과와 `preview.gif` 를 **1× 와 nearest-neighbor 4× 로 육안 검토**한다.
   특히 F55–80 경계(회전·접안 구간).
4. **움직임의 뼈대를 글로 적는다** — 어떤 비트가 왜 좋은지. 이게 3단계의 기준이 된다.

### 2단계 — 현재 진단 (결정 없이 가능)

1. `src/components/ui/LoadingScreen.tsx` 를 읽고 지금 트윈을 표로 적는다.
2. 앱을 띄워 오프닝을 **녹화**한다(웹 export + CDP, `capture-app.mjs --print-env` 로
   env 를 넘길 것 — 안 넘기면 조용히 mock 으로 돈다).
3. 1단계의 뼈대와 나란히 놓고 **없어진 비트를 목록으로** 만든다.
4. ⚠ 여기서 멈추고 §1 의 Simon 결정을 받는다.

### 3단계 — 파인튜닝과 재적용 (결정 이후)

1. **스프라이트 시트를 만든다.** 클로드 디자인 에셋의 스타일을 유지한 채
   아틀라스 셀 기하(96×96 정수 격자)에 맞춘 프레임 세트를 만든다.
   (b) 안이면 보행 대신 부유·기울임·바이저 점등·눈 깜빡임 세트다.
2. **결정적 합성기를 둔다.** `scripts/build-hustlek-opening.py` 와 같은 방식으로
   프레임을 만들고 해시로 검증한다. 손으로 합성하지 않는다.
3. **타임라인을 앱 길이로 압축한다.** 뼈대(등장 → 정착 → 시선 → 북극성)를 유지하되
   `MIN_INTRO_MS` 안에 첫 두 비트가 들어가야 한다. 자동 진행 4초를 넘기지 않는다.
4. **`LoadingScreen.tsx` 에 재적용한다.** 정지 이미지 트윈을 프레임 재생으로 바꾼다.
   ⚠ 이징은 `steps()` — PIXEL-CLAY 규칙 5. 프레임 애니메이션에 부드러운 곡선 이징을
   쓰면 픽셀이 흐려진다.
5. **성능을 잰다.** 지금 로고는 `expo-image` 를 쓴다 — 6MB 디코드를 매 부팅마다 하던
   문제(#857)를 피하려고 그렇게 한 것이다. 스프라이트 시트도 같은 함정이 있다.
   1254×1254 한 장보다 **작은 아틀라스 하나**가 낫다.
6. 검증: `npm run verify` 종료코드 0 · 실기기(또는 에뮬레이터) 콜드 스타트 육안 확인.
