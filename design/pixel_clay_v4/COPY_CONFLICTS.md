# 카피 충돌 보고서 — 브리프 원문 vs 구현 (2026-08-11)

> AUDIT_RESPONSE §10-3 요청분. 브리프는 "카피 원문 고정"이나, 이전 지시로 의도적으로 바꾼 지점이 있습니다.
> **PRD 세션 판정 요청**: 각 항목이 (A) 브리프로 되돌릴 것인지, (B) 구현을 정본으로 승격할 것인지.
> 되돌리지 않고 그대로 뒀습니다 — 판정 후 일괄 반영하겠습니다.

## 2. 어휘 정책 변경 — 전역 47곳 (사용자 지시)

> 지시: **"'비준 했어요' 같은 말은 너무 어려운말이야. 이런 어려운 말이 있다면 쉬운 말로 모두 변경해줘."**

| 브리프 어휘 | 현재 구현 | 영향 |
|---|---|---|
| 비준 | **확인** | propose→ratify 표기가 사용자 화면에서 사라짐 |
| 승인 이력 (`/ratifications` 제목) | **확인 이력** | 라우트 제목 |
| 승인 / 보류 / 거절 (필터 칩) | **맞아요 / 나중에 / 아니에요** | `/ratifications` 필터 갈래 |
| 검증틀 | 검사 | `/persona`·`/big-five` 계열 |
| 파생 신호 | 분석 결과 | `/import-hub`·`/privacy` |
| 온디바이스 우선 | 기기에서 먼저 | `/privacy` 한눈에 카드 |
| 열람 | 보기 | 전역 |
| 근거 | 이유 | 전역 |
| 한도 소진 | 다 썼어요 | `/reasoning`·`/plans` |
| 접수 | 요청을 받았어요 | `/subscription` |
| 추정 | 추측 | 검사 계열 |

**⚠ 이 변경이 브리프 불변식과 충돌할 수 있는 지점**
- `03-polaris /ratifications`의 카피 `제안 / 승인 / 보류 / 거절`은 **4열 요약 스트립의 열 이름**입니다. '맞아요/나중에/아니에요'로 바뀌면 "보류/거절은 항상 0" 이라는 정직성 표기의 의미가 달라질 수 있습니다.
- `07-wiki /review`·`06-capture` 등에서 반복되는 **"승인해야만 반영돼요"**는 유지했습니다(propose→ratify 원칙 문구).

## 4. 판정 요청 요약
1. **§1의 7건** — 사용자가 직접 지시한 삭제입니다. 브리프를 갱신할지, 구현을 되돌릴지 판정해 주세요.
2. **§2의 어휘 정책** — 전역 규칙이므로 브리프 렉시콘(PRD §15) 자체를 갱신하는 게 맞아 보입니다. 특히 `/ratifications` 열 이름은 별도 판단이 필요합니다.
3. **§3의 3화면** — 새로 받은 브리프로 재작성하면 해소됩니다. 지시 주시면 착수합니다.
