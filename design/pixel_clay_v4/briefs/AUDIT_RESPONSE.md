## 4. 레이아웃 분류 판정

- **windowed 통일 승인**: permissions·privacy·support·manual·법률 4종·notfound — 정본 코드는 과도기 상태(베어 창/레거시 셸)라, 구현의 windowed 통일이 오히려 셸 계약에 부합. **구현대로 가고 정본을 갱신한다.**
- **gate 레이아웃 승인**: auth·signup·pwreset·profilesetup·dobgate — 인증 트랙은 독 없는 풀스크린이 맞음.
- **재검토 2건**: ① `career` immersive → 도메인 렌즈 성격이면 **museum-like**(스크림+앱바) 권장. ② `srs`·`review`·`import-hub` immersive → 독·뒤로가기 동선만 확보되면 허용(고아 방지 확인 필수).

## 7. 미정의 6건 — 회신

### 7-1. CrisisRouter (위기 라우팅) 브리프
- **트리거**: 입력 분류가 red-zone 판정 시. LLM은 호출되지 않고 이 표면으로 단락. 쿼터 미차감.
- **형태**: 시스템 오버레이(풀스크린 시트). 현재 화면 위를 완전히 덮되, 닫으면 원래 화면으로 복귀(입력창의 원문은 비우고 저장하지 않음).
- **필수 요소**(배치 자유): ① 차분한 안내 1~2문장 ② 핫라인 행(전화 걸기 버튼 포함): KO 성인 **109** / KO 미성년 **1388**과 **109** 두 행 / EN **988** ③ [닫기] ④ "입력한 내용은 저장되지 않아요 · 횟수가 차감되지 않아요" 고지.
- **톤 규칙**: 차분한 뉴트럴 — 위험색(error)·경고 아이콘·애니메이션 금지. 세컨비 머리는 중립 무드 소형 1개까지만. 게이미피케이션·장식 0.
- **상태**: 단일 상태(4상태 불요). 전화 걸기는 OS 다이얼러로 위임.
- **카피**: 확정 원문이 앱 레포 `locales/ko/safety.json`에 존재 — 디자인은 자리·행 수만 맞추면 통합 시 원문 대입.

### 7-2. `/plans` 브리프 → **11-settings.md 동봉** (정직성 카드 원문·3티어 카피·법적 고지·리워드 행 포함)

### 7-3. 티어 명칭 — **확정**
사용자 노출명 = **별바라기 · 항해자 · 북극성** (내부 키 free/plus/pro). `05-secondb.md`에 보이는 free·soma·cortex·brain은 **구 내부 명칭 잔재** — 화면에 노출 금지. 한도: 채팅 일 5/80/250 · 리즈닝 주 2/7/무제한. 북극성은 "준비 중" 비활성 표기.

### 7-4. 밝기 L1~L5 — 단일 규칙 확정
- L1 = 기록 0건(꺼짐) · L2 = 1~4건 · L3 = 5~14건 **그리고** 카테고리/태그 구조 존재 · L4 = 15건 이상 **또는** 해당 도메인의 검증 측정도구 1개 완료 · **L5 = 사용자 비준으로만**.
- 교차검증(측정도구+행동 일치) 시 +1단계, 상한 L5. 표시 밝기 = 20%~100% 균등 매핑.
- 화면 간 다른 해석 금지 — 이 규칙 하나만 쓴다.

### 7-5. 알림 정책 — v1 확정
- **인앱만**: 백그라운드 작업은 도크+완료 토스트, 공지는 자동 팝업 1회+벨, 지인 응답 도착·리즈닝 완료는 인박스 벨 배지.
- **로컬 알림**: digest 9시 로컬 1건만 유지(기존 정의).
- **푸시**: 네이티브 빌드 게이트 후속 — 디자인 범위 밖. 화면에 푸시 설정 UI를 만들지 말 것(약속 금지).

### 7-6. EN 카피
EN 원문은 앱 레포 `locales/en/*.json`에 전 네임스페이스 존재(EN canonical, C7 패리티 CI 강제). **디자인은 KO만으로 진행**하면 되고, 통합 시 EN 자동 대입. 신규 화면(커뮤니티 등)도 EN 이미 랜딩됨.

## 8. ⚠ 시각 방향 — Simon 비준 필요 (이 회신의 유일한 큰 이슈)

이 프로토는 **PIXEL-CLAY v4**(Galmuri·radius 0·디더·스텝 모션)다. 현재 레포 캐논(DESIGN.md 2026-07-18)은 **Material 3 + deep-space**이고 **픽셀 폰트는 legacy 전용 금지**다. px-bridge(M3 어휘 유지) 아키텍처는 훌륭해서 기술적으로는 "스킨 레이어"로 이식 가능하지만, 방향 자체는 캐논과 정면 충돌한다.
- **Simon이 PIXEL-CLAY를 새 정본 시각으로 비준하면**: DESIGN.md·CLAUDE.md·브리프 00-SYSTEM의 시각 조항 개정 + "legacy(구 코스믹픽셀)"와 "신규 PIXEL-CLAY"의 구분 정의 필요. RN 포팅은 m3.ts 위 브리지 토큰 레이어로 계획.
- **비준하지 않으면**: 이 프로토의 구조·기능·4상태·플로우는 그대로 살리고, px-bridge 덕에 시각만 M3 cyan-dark로 되돌리는 비용이 낮다(브리지 토큰 정의부 교체).
- 어느 쪽이든 **구조 작업은 유효** — 이 감사의 승인 사항들은 시각 결정과 독립.
