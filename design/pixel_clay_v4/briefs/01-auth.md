## 로그인 (`/sign-in`) — fullscreen
목적: 미인증 사용자의 앱 진입 관문. 이메일+비밀번호 로그인과 소셜 로그인(구글/애플/카카오/페이스북/깃허브/네이버)을 한 화면에서 제공하고, 회원가입·비밀번호 재설정·약관으로 분기한다. 로그인 성공 시 '/'로 이동해 IntroGate 로딩 후 별자리 홈으로 진입한다.

기능 · 필수 컨트롤:
- 이메일/비밀번호 입력 후 '로그인' 탭 또는 키보드 go → signInWithEmail 호출. 성공 시 router.replace('/') — IntroGate 로딩 후 홈. 실패 시 danger 토스트 '로그인에 실패했어요. 이메일과 비밀번호를 다시 확인해 주세요.' (계정 존재 여부 비노출, 열거 방지)
- 비밀번호 보기/숨기기 토글 탭 → secureTextEntry 토글
- 소셜 아이콘 탭 → 해당 provider OAuth 시작(브라우저/커스텀탭). 'provider not enabled' 오류면 그 버튼을 세션 동안 숨기고 danger 토스트 '{{provider}} 로그인을 시작하지 못했어요…'
- Naver 아이콘 탭 → 커스텀 OAuth 시작(signInWithNaver). 복귀는 /oauth-callback 이 처리
- '비밀번호를 잊으셨나요?' 탭 → router.push('/reset-password', { email }) — 입력한 주소를 갖고 이동해 재입력 없이 코드 요청
- '가입하기' 탭 → router.push('/sign-up')
- 법적 고지 문구 탭 → router.push('/terms')
- Android 하드웨어 Back → router.push('/') — 앱 종료 대신 별자리 홈으로(비로그인도 홈 셸은 보임)
- 이미 로그인 상태로 진입 → <Redirect href='/'>로 즉시 이탈

담아야 할 정보 묶음(구성 자유): 히어로 · 이메일 로그인 폼 · 소셜 로그인 · 회원가입 유도 + 법적 고지

4-상태: empty: 기본 상태 = 빈 폼. 별도 empty 뷰 없음. / loading: 세션 확인 중이면 화면 전체를 InlineLoader 로 대체(로그인 폼 플래시 방지). / error: danger 토스트(로그인 실패/OAuth 시작 실패). 폼은 유지. / filled: 이메일 @ 포함 + 비밀번호 1자 이상이면 CTA 활성.

게이팅(불변): auth: guest-only (로그인 상태면 '/'로 리다이렉트) · consent: 약관 동의는 문구 고지 방식(체크 없음) — 실제 동의 수집은 sign-up
안전(불변): 로그인 실패 메시지는 이메일 존재 여부를 드러내지 않는다(CSO R3). 크리시스/쿼터 무관.
이동 대상: /, /sign-up, /reset-password, /terms

## 회원가입 (`/sign-up`) — fullscreen
목적: 이메일+비밀번호+생년월일로 계정을 만드는 화면. C10 연령 게이트(만 14세 이상)와 PIPA 동의 원장(필수 4항목 + 선택 마케팅)을 여기서 수집하고, 가입 후 메일로 온 6자리 확인 코드를 같은 화면에서 입력해 가입을 완료한다. 소셜 가입 시 생년월일·동의는 /complete-profile 로 미룬다.

기능 · 필수 컨트롤:
- '계정 만들기' 탭 → submitSignUp: supabase.auth.signUp + 동의 원장 기록(recordConsentBestEffort, 내비게이션 전에 await). 결과 분기 — confirmationRequired: 확인 카드 표시 / entered: router.replace('/') / ageGate: danger 토스트 '두번째 뇌는 만 14세 이상부터 이용할 수 있어요.' / breachedPassword: '이 비밀번호는 알려진 유출 목록에 있어요…' / maybeExistingAccount: 기존 계정 카드 / 기타: '가입에 실패했어요…'
- 심사관 도메인 이메일(C6: @xprize.org 등)로 가입 성공 → success 토스트 '환영합니다. 전체 접근 권한이 활성화됐습니다.' 900ms 후 '/' 진입 (judge_mode 자동 플래그)
- 확인 코드 6자리 입력 후 '코드 확인' → verifySignUpCode -> 성공 시 세션 성립 + refresh, 카드 해제, guest 가드가 '/'(또는 /complete-profile)로 라우팅. 실패 시 '코드가 맞지 않아요. 최신 메일의 코드로 다시 시도해 주세요.'
- 이메일 주소 수정 → 확인 카드·기존계정 카드·info 토스트 즉시 해제(주소에 종속된 상태 무효화)
- 동의 행 체크 영역 탭 → 해당 항목 토글. '필수 항목에 모두 동의'는 필수 4개 일괄 토글
- 동의 행 우측 › 탭 → router.push('/consent-notice?item=<key>') — 해당 섹션으로 스크롤·하이라이트
- 소셜 아이콘 탭 → OAuth 시작. 성공 복귀 시 프로필 없으면 index 리다이렉트로 /complete-profile (생년월일+동의를 거기서 수집)
- 가입 확인 메일 딥링크로 앱 재진입(네이티브) → consumeAuthCallbackUrl 로 토큰 소비 -> 세션 성립 -> 카드 해제 후 온보딩/홈으로
- Android 하드웨어 Back → router.push('/')
- 이미 로그인 상태(제출/토스트 중 아님) → <Redirect href='/'>

담아야 할 정보 묶음(구성 자유): 히어로 · 이메일 확인 카드 (조건부, 가입 제출 후 최상단) · 가입 정보 카드 · 동의 카드 (DeepSpaceConsentBlock) · 기존 계정 안내 카드 (조건부) · 소셜 가입 카드 · 제출 + 하단 링크

4-상태: empty: 빈 폼 + 히어로. 체크리스트 숨김. / loading: 세션 확인 중 InlineLoader 전체 화면. / error: danger 토스트(ageGate/breached/실패) 또는 지속 카드(기존 계정). / filled: 모든 조건 충족 시 CTA 활성. 제출 성공 후에는 '이메일 확인 카드'가 화면의 주 상태.

게이팅(불변): auth: guest-only · minor: 만 14세 미만은 가입 차단(C10). 14-17은 minor_self 동의 밴드 + 높은 프라이버시 배너 · consent: 필수 4항목(서비스/LLM 처리/국외 이전/민감정보 취급) 전부 체크해야 제출 가능. 마케팅은 선택
안전(불변): 기존 계정 카드 카피는 계정 존재를 확정하지 않는 조건부 문장(열거 방지). 확인 메일은 코드-온리(Gmail 링크 평판 이슈 대응). 동의 원장은 C10/PIPA 증빙.
이동 대상: /, /sign-in, /consent-notice, /terms

## 비밀번호 재설정 (`/reset-password`) — fullscreen
목적: 비밀번호 복구 전체(코드 요청 -> 6자리 인증 -> 새 비밀번호 설정 -> 완료)를 한 화면 4단계로 처리한다. 로그인 화면에서 입력한 이메일을 param 으로 이어받아 재입력을 줄이고, 재설정 메일의 딥링크(recovery 세션)로 진입해도 같은 화면의 password 단계로 이어진다.

기능 · 필수 컨트롤:
- '인증번호 보내기'/재전송 탭 → sendPasswordResetEmail. success 토스트 '인증번호를 보냈어요. 메일함을 확인해 주세요.' + 60초 쿨다운. 실패 시 열거 방지 동일 문구 '재설정 링크를 보내지 못했어요…'
- '인증번호 확인' 탭 → verifyPasswordResetCode -> 성공 시 recovery 세션 성립, userId 가 서면서 화면이 password 단계로 자동 전환. 실패 시 '인증번호가 맞지 않아요. 최신 메일의 번호로 다시 시도해 주세요.'
- '비밀번호 변경' 탭 → updatePassword -> 성공 시 done 단계 + success 토스트 '비밀번호를 변경했어요.' 실패 시 '비밀번호를 변경하지 못했어요. 링크가 만료됐다면 새 링크를 요청해 주세요.'
- '계속하기' 탭 (done) → router.replace('/')
- 재설정 메일 딥링크로 진입(네이티브) → consumeAuthCallbackUrl 로 recovery 토큰 소비 -> password 단계

담아야 할 정보 묶음(구성 자유): 히어로 · 단계 카드 — request/verify · 단계 카드 — password · 단계 카드 — done

4-상태: empty: request 단계 빈 이메일 폼(sign-in 에서 넘어오면 프리필). / loading: AuthContext 로딩 중 InlineLoader 전체 화면. / error: danger 토스트(전송/검증/변경 실패) + password 단계는 인라인 헬퍼 오류. / filled: 단계별 CTA 활성 조건 충족 시. done 단계 = 성공 종결 상태.

게이팅(불변): auth: request/verify 는 비로그인 가능. password 단계는 recovery 세션(userId) 필요
안전(불변): 코드 전송 결과 문구는 계정 존재를 드러내지 않음(CSO R3). 재전송 60초 쿨다운.
이동 대상: /sign-in, /

## 프로필 완성 (한 가지만 더) (`/complete-profile`) — fullscreen
목적: 소셜(OAuth) 로그인으로 auth 유저는 생겼지만 public.users 프로필이 없는 사용자에게 생년월일(C10 연령 게이트)과 PIPA 동의를 받아 프로필을 완성시키는 강제 관문. 통과해야 앱 본체로 진입한다.

기능 · 필수 컨트롤:
- '계속' 탭 → submitCompleteProfile: ensureUserProfile(birthDate, locale)로 users 행 생성 + 동의 원장 기록(await) + 컨텍스트 refresh 후 분기 — entered: router.replace('/') / judge: '환영합니다…' 토스트 900ms 후 '/' / emailInUse: danger 토스트 '이미 이 이메일로 만든 계정이 있어요. 처음 가입했던 로그인 방법으로 다시 로그인해 주세요.' 1.6초 후 로그아웃 -> /sign-in / ageGate: '두번째 뇌는 만 14세 이상부터…' 토스트 0.9초 후 로그아웃 -> /sign-in / 실패: '프로필 저장에 실패했어요…'
- '취소하고 로그아웃' 탭 → signOutAndSettle -> 성공 시 router.replace('/sign-in'), 실패 시 '로그아웃하지 못했어요…' 토스트
- 동의 행 탭 → 항목 토글 / '필수 항목에 모두 동의' 일괄 토글 (상세 › 링크는 없음 — sign-up 과의 델타)
- 프로필이 이미 있는 상태로 진입 → <Redirect href='/'>
- 비로그인 진입 → <Redirect href='/sign-in'>

담아야 할 정보 묶음(구성 자유): 딥스페이스 배경 · 헤더 · 폼 카드

4-상태: empty: 빈 생년월일 + 미체크 동의. CTA 비활성. / loading: 세션/프로필 확인 중 및 프로필 프로브 일시 실패 시 InlineLoader '확인하는 중…' (등록된 유저에게 폼을 잘못 보여주지 않기 위한 홀드) / error: danger 토스트 후 케이스별 강제 로그아웃 이동. / filled: 생년월일 유효 + 필수 동의 완료 시 '계속' 활성.

게이팅(불변): auth: 로그인 필수(비로그인 -> /sign-in). 프로필 보유자는 진입 불가('/') · minor: 만 14세 미만 입력 시 서버 AgeGateError -> 로그아웃 처리(C10). 14-17 은 미성년 배너 + minor_self 동의 밴드 · consent: 필수 4항목 체크 없이는 진행 불가
안전(불변): emailInUse 좌초 계정 탈출 경로 제공(원래 가입 방법 안내 후 로그아웃). 동의 기록은 best-effort 지만 내비게이션 전에 await(웹 race 방지).
이동 대상: /, /sign-in
