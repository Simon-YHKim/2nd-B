# 코덱스 인계 — UI/UX 이주와 파인튜닝 (2026-08-27)

다른 PC 의 코덱스가 **화면 인터페이스를 레퍼런스에 맞춰 올리는** 작업을 이어받기 위한 문서다.
이 파일은 프롬프트이자 계약이다. 먼저 읽고, 아래 §7 블록을 코덱스에 넣는다.

---

## 0. 먼저 — 이 문서가 정정하는 것

발주 원문은 *"일정한 평가 기준에 대해 98점 이상"* 을 요구한다. 그 요구는 옳지만
**지금 저장소에 있는 눈금으로는 98 을 낼 수 없다.** 이유를 먼저 적는다.

기존 대조 수치 `textMatchPct` 는 레퍼런스 화면의 **텍스트 노드 5~13개** 중 앱에도
있는 비율이다(실측: `data/app-compare*.json`).

| 화면 | 레퍼런스 텍스트 노드 | 노드 하나의 가치 |
|---|---:|---:|
| `home` · `chat` | 5 | **20점** |
| `interview` | 6 | 16.7점 |
| `me-star` · `trend` | 8 | 12.5점 |
| `review` | 13 | 7.7점 |

**한 노드가 8~20점이다.** 이 눈금에서 98 은 100 과 같은 말이고, 100 은
"레퍼런스 목업의 가짜 문장까지 그대로 베껴라"는 뜻이 된다. 그건 디자인 품질이
아니다 — 실제로 `digest`·`insights` 같은 화면은 레퍼런스가 목업 데이터라
**베끼면 오히려 틀린다.**

그래서 이 문서는 **해상도가 있는 5축 합산 점수**를 정의한다(§3). 98 은 거기서
의미를 갖는다.

### ⚠ 레퍼런스가 자동으로 옳지는 않다

발주가 명시했다 — *"화면 간 연결 구조와 화면의 구성을 화면의 역할과 목적에 집중하여
수정 가능"*. 그래서 이 계약은 **의도적 이탈**을 1급으로 다룬다(§4). 레퍼런스를
베끼는 것이 목적이 아니라 **그 화면이 제 역할을 하게 만드는 것**이 목적이다.

실제로 레퍼런스가 틀린 사례가 이미 기록돼 있다:

- `record` 프레임은 '별가루 **상세**'인데 앱 `/records` 는 '목록'이다 → 같은 DOM 을
  두 번 재서 71% 라는 **거짓 수치**가 나왔다(`app-routes.json` 의 `unmapped` 참조).
- `privacy`·`support` 는 **우리 문서가 정본**이라 레퍼런스 카피를 따르면 안 된다.
- 레퍼런스 `profile` 은 글자 6개 중 5개가 **독(dock) 라벨**이라, 독이 없으면
  자동으로 17% 가 된다 → **카피가 아니라 구조 문제다.**

## 2. 작업 범위 — "모든 화면" 을 정의한다

```
레퍼런스 프레임          93
  └ port:true            86   ← 이식 대상
      └ 라우트 매핑됨    35   ← 지금 잴 수 있는 것
      └ 매핑 없음        51   ← 작업 0 에서 늘린다
  └ port:false            7   ← 손대지 않는다(사유 있음)
```

**작업 0 (선행).** `app-routes.json` 의 매핑을 35 → 가능한 만큼 늘린다.
출처는 `src/lib/dev/screen-index.ts` 의 `href` 값이다(테스트가 `src/app` 라우트 파일과
1:1 대조한다). ⚠ **억지 매핑 금지** — 확신이 안 서면 `unmeasurable`/`unmapped` 에
사유와 함께 적는다. 파일 자신이 그렇게 적어놨고, 억지 매핑은 대조 수치를 거짓으로 만든다.

**순번을 지킬 것.** stage 1 은 8화면(일곱 한 벌과 진입 경로), stage 2 가 72개다.
한꺼번에 옮기면 어디서 깨졌는지 못 찾는다.

## 3. 평가 기준 — 5축 100점

화면 하나마다 아래를 합산한다.

| 축 | 배점 | 무엇을 재나 | 도구 |
|---|---:|---|---|
| **A. 픽셀 규율** | 30 | 그 라우트의 DOM 에서 곡선·라운드·블러·정적 반투명 **위반 수** | `tools/rules/dom-{curves,radius,alpha}.mjs` **있음** |
| **B. 토큰 충실도** | 25 | 그 화면이 칠한 색이 `tokens.json` 램프로 해결되는 **면적 비율** | **새로 쓸 것** |
| **C. 구조 일치** | 20 | `structure/<id>.json` 대비 섹션 순서·개수·상대 크기 | 다이제스트 있음, 비교기 **새로 쓸 것** |
| **D. 내비 무결성** | 15 | 진입·복귀·독 링크가 `nav.json` 이 말하는 곳으로 가는가 | **새로 쓸 것** |
| **E. 카피 커버리지** | 10 | 기존 `textMatchPct` | `capture-app.mjs` **있음** |

### 채점 방식

- **A**: 위반 0 이면 30점. 위반 1건당 −6, 5건이면 0점. (규칙 1·2·3 은 이미 화면
  실측 0~1 이라 대부분 만점에서 출발한다.)
- **B**: `면적비 × 25`. 캐논 램프 밖 색이 칠한 화소 면적을 pngjs 히스토그램으로 센다.
  ⚠ **바탕색 두 개가 표면 토큰 전부보다 크게 움직인다**(`m3.accent.cosmicBase`
  `#060912`·`stageFloor` `#070A13`). 토큰 파일만 보면 못 찾는다.
- **C**: 섹션(깊이 3 이하 박스) 순서 일치율 × 10 + 개수 일치 × 5 + 상대 높이 오차
  10% 이내 × 5.
- **D**: `nav.json` 이 그 화면에 대해 선언한 링크 중 실제로 그 라우트로 가는 비율 × 15.
- **E**: `textMatchPct × 0.1`. **배점이 낮은 이유는 §0 의 해상도 문제다.**

### 98 이 무슨 뜻인가

배점상 **잃을 수 있는 총량이 2점**이다. E 의 한 노드가 2점(5노드 화면)이므로
**"레퍼런스 문장 하나까지는 다를 수 있다"** 가 98 의 실질적 의미다. 의도적으로
빡빡하게 잡았다.

### ⚠ 98 은 게이트지 완성이 아니다

여백의 리듬, 픽셀의 손맛, 애니메이션 타이밍의 체감, 카피의 온도는 **점수로 만들지
않는다**(Tier 3). 자동 점수 ≥98 **그리고** 사람 눈 통과 — 둘 다여야 완료다.
점수를 올리려고 Tier 3 을 희생하면 그건 실패다.

## 4. 의도적 이탈 — 레퍼런스를 안 따를 때

`design/pixel_clay_260825/data/deviations.json` 을 새로 만들어 기록한다.

```json
{
  "note": "레퍼런스와 **일부러** 다르게 간 것. 사유 없는 항목은 이탈이 아니라 결함이다.",
  "deviations": [
    {
      "screen": "records",
      "axis": "C",
      "what": "레퍼런스 record(상세) 프레임 대신 목록 구성을 유지",
      "why": "앱 /records 는 목록이고 상세는 /record/<id> 다. 프레임을 따르면 두 화면이 한 DOM 이 된다.",
      "decidedBy": "codex",
      "date": "2026-08-27"
    }
  ]
}
```

**채점기는 기록된 이탈을 감점하지 않는다.** 대신:

- `why` 가 비어 있으면 **감점**한다(면제가 공짜면 전부 이탈이 된다).
- `decidedBy: "simon"` 인 항목은 코덱스가 되돌릴 수 없다.
- 이탈 총수가 그 화면 축 배점의 절반을 넘으면 **사람 확인 대상**으로 표시한다.

## 5. 반복 루프

```
for 화면 in 순번(stage1 → stage2):
    1. 확인   레퍼런스 캡처 + 구조 + 현재 앱 캡처를 나란히 놓고 어긋난 곳을 적는다
    2. 개선   한 번에 한 화면. 커밋도 한 화면.
    3. 검증   점수 재측정 + npm run verify (종료코드로 확인)
    4. <98 이면 1 로. 3회 반복해도 안 오르면 멈추고 사유를 적는다.
```

**3회 규칙이 중요하다.** 안 오르는 화면은 대개 카피가 아니라 **구조나 하네스**가
원인이다. 실제 사례: `/profile` 이 33% 였던 것은 카피 부족이 아니라 **딥스페이스 셸
전환 자체가 없어서**였다. 계속 카피를 만지면 영원히 안 오른다.

## 6. 밟으면 안 되는 함정 (전부 실제로 밟은 것)

1. **소스 grep 으로 위반을 세지 말 것.** `<Path` 만 세면 문자열 `'<path …>'`(SvgXml)를
   놓친다 — 실측 121 로 셌는데 실제 320 이었다. 화면 DOM 으로 셀 것.
2. **개발 전용 라우트(`DevOnlyRoute`)를 목록에 넣지 말 것.** 로그인 세션에서 홈으로
   리다이렉트돼 **홈이 두 번** 세어진다(`/trends` 로 실제 겪음).
3. **워드 조이너 `U+2060`.** 앱이 심는 이 글자가 문자열 비교를 깨뜨려 **있는 문장을
   없다고** 셌다. 도구 수정만으로 33→55 가 됐다 — 옛 수치를 인용하지 말 것.
4. **`EXPO_PUBLIC_*` 를 안 넘기고 export 하면 앱이 에러 없이 조용히 mock 으로 돈다.**
   `capture-app.mjs --print-env` 를 쓸 것.
5. **시각을 고정하면 로그인이 깨진다.** 고정 시각이 토큰 발급보다 뒤면 세션이 만료로
   보여 **모든 화면이 로그인 월로** 찍힌다(캡처는 성공, 대조만 0%).
6. **baseUrl 이 `/2nd-B`.** dist 를 그냥 서빙하면 에셋 404 에 `Unexpected token '<'` 만 남는다.
   그리고 `/2nd-B/index.html` 이 아니라 `/2nd-B/` 로 열 것.
7. **온보딩은 매 이동마다 다시 뜬다.** 화면마다 밀어내야 한다.
8. **낮은 점수 ≠ 카피 부족.** 구조를 먼저 의심하고 카피는 그 다음이다.
9. **정규식을 heredoc 에 넣지 말 것.** 백슬래시가 사라져 가드가 조용히 무력화된다.
10. **`npm run verify` 는 파이프 없이 종료코드로 확인.** `| grep` 은 grep 의 코드다.

## 8. 이 문서가 답하지 못하는 것

1. **픽셀 비교(SSIM)는 없고, 이 저장소에서 의미가 약하다.** RN-web 렌더와 번들 DOM 은
   애초에 다른 엔진이다. B 축의 색 면적비가 그 대체물이다.
2. **레퍼런스 번들은 목업 데이터다.** 레이아웃과 연결이 레퍼런스고, 값은 저장소 실물이 정본이다.
3. **컴포넌트 렌더 테스트가 업스트림 문제로 막혀 있다**(RN 0.85 + jest). 그래서 채점은
   실제로 웹 export 를 띄워 재는 방식뿐이다.
